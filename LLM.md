# LLM Context — 12V Sim

> **Read this first** before answering any question about this project.
> **Always update this file** when behavior, architecture, or scope changes — treat `LLM.md` as part of the deliverable for any non-trivial PR or agent session so future prompts stay accurate.

## 1. What this is

Browser-based, drag-and-drop simulator for **any 12 V DC electrical system** — car, camper, van, boat, off-grid shed, robot, e-bike, anything 12 V.
The user wants to prototype, stress-test, and share schematics before cutting real wires. End goal: catch blown fuses, voltage drop, melted wires, brown-outs, dead batteries — anything that would bite in the real install. The app is intentionally domain-agnostic; component descriptions reference real product categories from the boat / RV / automotive / off-grid worlds because that's where 12 V DC product lines come from, but the canvas works for any 12 V topology.

Static SPA, no backend. Designs save to LocalStorage, export/import as JSON, share via URL hash. Deploy `dist/` to Vercel / Cloudflare Pages / GitHub Pages / any static host.

## 2. Status

**Phase 1 (MVP) — complete.** DC steady-state Modified Nodal Analysis solver, drag/drop canvas, palette, inspector, autosave, share URL, multi-select with box-drag, resizable nodes, blown-fuse / wire-overload / brown-out detection, animated energized wires, StatusBar alarm messages plus optional locale-driven plain-language explanations (`alarms.explanations.*`).

**Port handles + palette polish:** React Flow handle dots use a **six-way `Polarity`** union (`src/sim/types.ts`) mapped through `portColor()` in `ComponentNode.tsx` — red/black for true ± poles, **amber** for switched/fused outputs (`fuse.b`, `fusebox`/`switchPanel` circuit outs, `relay`/`mosfetSwitch` switched pins, `selector.c`, `rotary.c`), **violet** for `potentiometer.w`, **green** for `ground.g`, **slate** for pass-through (`wire`, `dimmer`, `switch`, etc.). Tier-C preset tables (`schema.ts`) were re-skinned so previously twin-looking palette cards read differently at a glance (ammeter vs voltmeter LCD/analog, oscilloscope 1ch/2ch/4ch chassis tint, shunt amp tiers, `controller.pwm` square-wave glyph vs timer relay ⏱, smart relay module 📲 vs battery-monitor SmartShunt 📶, generic `load` 🔌 vs `usbCharger` 📱 vs dome lamp 💡, rocker teal gradient vs toggle sky). **`Canvas.tsx` MiniMap `nodeColor`** adds explicit dots for `fusebox`, `switchPanel`, `busbar` (by `params.polarity`), and `wire`, and tracks the updated preset MiniMap hex colours.

**Palette search input:** sticky text field at the top of the palette (between the header and the scrollable category list) live-filters cards as the user types — case-insensitive substring match against `label + description` only (the same two strings the user sees on the card). Earlier versions also matched the `wiringGuide` but that surfaced too many incidental hits from the longer educational copy and made results feel noisy; keep the search corpus tight to what's visually on the card. Categories with zero matches are hidden entirely; categories with matches are force-expanded for the duration of the search via an `effectiveCollapsed = isSearching ? new Set() : collapsed` override (the persisted `collapsed` set in LocalStorage is NOT mutated, so clearing the input restores the user's saved layout exactly). The category-header chevron is `disabled` while searching so the search-driven open state isn't fightable. Matched substring inside the card label is wrapped in an amber `<mark>` via a tiny `HighlightedLabel` helper. Empty-result state renders a "No components match \"...\"" message + "Clear search" button instead of the category list. Esc inside the input clears it (or blurs when already empty); strings live under `palette.search*` in `en.json`.

**Palette as educational tool (info-icon popover):** every palette card carries a small italic `i` button on its right edge. Hovering (120 ms open delay so diagonal mouse paths don't flicker) or focusing the icon opens an `InfoPopover` portaled to `document.body` (same `createPortal` trick as `DesignsModal` to escape the toolbar's `backdrop-blur` containing-block trap and the palette's `overflow-y-auto` clip). The popover is anchored to the icon's `getBoundingClientRect()`, defaults to right-of-icon, and auto-flips to left-of-icon when `rect.right + POPOVER_WIDTH (340)` would overflow. Two sections: **"What it is"** (full untruncated description, replaces the old native `title=` tooltip) and **"How to wire it"** (new beginner guidance — wire colours, fuse rules, common gotchas — sourced from `components.<type>.wiringGuide` for plain cards, with variant cards reading `paletteVariants[].wiringGuide` first and falling back to the type-level guide). Icon button has `nodrag nopan`, `onMouseDown` stopPropagation, and `draggable={false}` so it never initiates a card drag. Strings live under `palette.popover.{whatItIs,howToWire}` + `palette.infoTitle`. **Adding wiring content for a new component is one `wiringGuide` string in the type's locale block; for a new preset variant, one `wiringGuide` string under `components.<type>.presets.<id>.wiringGuide` (or `.modes.<id>.wiringGuide` for the controller).** Both keys are optional — a missing guide just hides the "How to wire it" section.

**Selector switch (1-2-BOTH-OFF):** marine 3-port battery selector under `Switching & Control`. Two battery inputs (`i1`, `i2`) feed a common output (`c`) via two independent contacts. The `position` param (`off | 1 | 2 | both`) opens/closes each contact: OFF leaves both at `R_OPEN`; `1` / `2` close just that leg; `both` closes both, paralleling the inputs (and tying them to each other through the switch). On-canvas inline cycler button (`OFF → 1 → 2 → BOTH`) lives next to the existing SPST toggle pattern. The runtime badge shows V at the common rail and total current through C.

**Switch presets (toggle / rocker / pushButton / momentary / killSwitch):** all five live as **palette variants of the same `switch` `ComponentType`** — same SPST resistor stamp, different visuals + click semantics. The lookup table is `SWITCH_PRESETS` in `src/sim/schema.ts` (mirrors `LAMP_PRESETS` / `APPLIANCE_PRESETS` — Tier C in §11): each spec carries a glyph, body gradient, MiniMap colour, and the `latching` + `normallyClosed` defaults that get baked onto `params` when the preset card is dropped (via `paletteVariants`). Click semantics live in `ComponentNode.tsx`: latching presets toggle `params.closed` on click; momentary presets flip `closed` to the active state on `mousedown` and revert on `mouseup` / `mouseleave` — the rest state is `normallyClosed` (NC: rest closed → press opens; NO: rest open → press closes). Three dedicated body components (`RockerBody`, `RoundButtonBody`, `KillSwitchBody`) render the visuals; the existing inline pill-toggle stays for the default `toggle` preset so legacy designs render unchanged. Inspector exposes `preset`, `latching`, `normallyClosed`, and `closed` so the user can mix-and-match (e.g. take a "rocker" preset and make it momentary by flipping `latching` off). Picking a new preset routes through the dedicated `setSwitchPreset(id, presetId)` store action, which updates `params.preset` and re-seeds the preset's `latching` / `normallyClosed` defaults; engagement state is preserved across latching↔latching swaps and snapped to rest state otherwise. MiniMap colour is also preset-driven (green = horn / push button, red = kill switch, amber = momentary NC, **teal** = rocker — distinct from toggle sky, default sky for toggle).

**Rotary selector (`rotary`):** generic N-position rotary switch under `Switching & Control` — distinct from the marine `selector` (1-2-BOTH-OFF) which keeps its own component type for the BOTH parallel mode. `rotary` is a **dynamic-port** component (Tier B in §11): `params.positionCount` (2–12, default 4) drives `getPortsForNode` via `buildRotaryPorts`, which lays out one common port (`c`) on the right plus N input ports `i_1`…`i_N`. For low N (≤4) all inputs sit on the LEFT edge stacked vertically; higher counts wrap the middle ones onto the BOTTOM edge so the body doesn't get crowded. Port IDs stay stable across resize so designs survive `positionCount` changes (same dangling-edge behaviour as fusebox sockets / busbar taps). `params.position` is 1-indexed (0 = OFF, no leg closed). The MNA stamp emits one resistor per `i_k → c` (active leg = `contactR`, others = `R_OPEN`) — generalised version of the `selector` with no BOTH mode. `RotaryBody` renders a circular dial with a rotating indicator arrow, position labels around the perimeter (1..N or preset-supplied names like OFF/ACC/RUN/GLOW/START), and clickable label buttons; clicking the dial centre advances OFF → 1 → … → N → OFF. Two palette variants ship: generic `rotary` (numbered) and `keySwitch` (gold ring, ignition labels — `RotaryPreset` table in `schema.ts` → adding a third preset is one entry + one locale block). Inspector `positionCount` writes route through `setRotaryPositionCount(id, n)` which clamps + flushes React Flow's handle cache via the `useUpdateNodeInternals` effect (`rotaryPositionCountForEffect` is in the dep list); `position` is also clamped into the new range on shrink so a rotary that was on leg 8 falls back to OFF instead of pointing at a non-existent leg. `internalConnections` in `review.ts` walks `c ↔ i_*` regardless of which leg is currently active so the protection BFS treats every input as a potential live path (a rotary off leg 3 is just as unprotected as the live one — the user could rotate to it any moment).

**Dimmer (rheostat) (`dimmer`):** simple 2-terminal variable resistor (Tier A primitive). MNA stamp is a single resistor `R = minR + (1 − value) × maxR` between `a` and `b` (defaults `minR = 0.5 Ω`, `maxR = 50 Ω`, `value` = 0..1 → 0..100% brightness in the UI). Real marine LED installations use PWM dimming via the existing `controller` component — `dimmer` models the older incandescent / halogen rheostats and resistive analog dimmers, with an honest description that points the user at `controller` for digital dimming. `DimmerBody` renders an interactive horizontal slider with a draggable knob and live brightness percentage readout — pointer-capture pattern means dragging the knob outside the body keeps tracking. Inspector swaps the `value` numeric field for a `SliderField` (range slider + number input pair) per the new `SLIDER_KEYS` set; both surfaces write to the same `value` param so they stay in sync. Reviewer treats the dimmer as a transparent series resistor — `walkDownstreamCables` and `isLoadUnprotected` walk through it just like a switch / wire so loads downstream stay under the upstream fuse umbrella.

**Potentiometer (`potentiometer`):** 3-terminal variable resistor (Tier A primitive, polarized). Two MNA resistor stamps split the track between A↔W and W↔B based on `params.position` (0..1 wiper position): `R_aw = max(minR, position × maxR)`, `R_wb = max(minR, (1 − position) × maxR)` — defaults `maxR = 1 kΩ` (standard control pot), `minR = 1 Ω` (end-stop minimum keeps the matrix non-singular). Wiper port `w` sits on the TOP edge (centered); `a`/`b` are on the left/right. Wiring W to anything reads the divider voltage — useful for gauge senders, joystick inputs, analog dimmers as a 3-terminal voltage source. `PotBody` renders a horizontal track with a triangular wiper pointer that drags in sync with `position`; live wiper voltage is shown when the simulator is running. `internalConnections` walks `a ↔ w ↔ b` (wiper is a real junction — current can flow in either direction through the track). Polarized (in `POLARIZED` set across `ComponentNode.tsx` / `Inspector.tsx` / `Canvas.tsx`) so the user can swap A and B via the corner ⇄ button when wiring sense direction matters. Same `SliderField` pattern as the dimmer for `position` editing.

**Editor QoL (also done):** per-node rotation (4-way) and pole-flip, duplicate (Ctrl/Cmd+D, multi-select aware), right-click context menu on components (rotate / swap poles / duplicate / delete), magnetic alignment snap with pink guide lines while dragging (Alt to bypass), and fattened resize hit areas around the selection ring.

**Cursor affordances (`index.css`):** native clickable controls (`button`, checkbox/radio, `select`, `summary`, links, …) use `cursor: pointer` so toolbar / palette / inspector / modals read consistently — palette component cards intentionally keep **`cursor-grab` / active `grabbing`** on the draggable DIV (HTML5 drag) so drag affordance stays obvious. Canvas viewport pane forces **`grab` / `grabbing`** while React Flow considers the pane draggable or actively pan-dragging; this overrides xyflow's `.selection → pointer` rule that previously hid pan cursors when `selectionOnDrag` is enabled (`Canvas.tsx`).

**Power-distribution family (`terminalBlock`, `groundingPoint`, `junctionBox`, `distributionPanel`):** four electrically-distinct distribution components added under `Wiring` and `Protection` categories. **`terminalBlock`** is a barrier strip with N **independent** rows (`rowCount`, 2–16, default 6) — each row `r{k}_a ↔ r{k}_b` is its OWN electrical node (rows are NOT cross-connected). Use this to land multiple wires per circuit without commingling unrelated circuits like a busbar would. **`groundingPoint`** is an N-stud bonding bus (`studCount`, 2–16, default 6) automatically tied to electrical node 0 inside `netlist.ts`'s ground-roots collection — exactly like a `ground` component but with N studs. Distinct from a negative `busbar` (no auto-ground tie) and from `ground` (single port). **`junctionBox`** is a sealed enclosure with TWO galvanically-isolated splice clusters (`groupAPortCount` / `groupBPortCount`, each 2–8, default 4) each with its own `groupAPolarity` / `groupBPolarity` render hint (positive / negative / ground / neutral); netlist pre-unions every `a_*` port together and every `b_*` port together but the two groups stay separate electrical nodes. **`distributionPanel`** is the integrated marine subpanel: ONE main breaker on the line side + N per-circuit branches (`circuitCount`, 2–12, default 6), each with its own resettable breaker (`circuits[k].ratingA` / `tripped`, modelled with the new `BreakerChannel` interface in `types.ts`), on/off rocker, and energized LED. The MNA stamp emits one resistor per channel (`Rc + coldR` when the AND of `mainClosed`, `!mainTripped`, `channel.closed`, `!channel.tripped` is true; `R_OPEN` otherwise). The iterative trip-detection loop has TWO tiers — per-circuit breaker (same shape as fused switchPanel, alarm `alarms.breakerTripped`) AND a MAIN-breaker check that compares Σ |I_branch| against `mainBreakerRatingA` and trips the synthetic key `${id}::main` (alarm `alarms.distributionPanelMainTripped`) when exceeded, killing every channel via the `mainGate` AND. Distinct from `fusebox` (single-shot fuses), `switchPanel` with fuses (no integrated main, no per-channel energized LED). All four components are Tier B in §11; `Inspector.tsx` exposes count + per-channel editors (`BreakerChannelsEditor`) and dedicated reset actions (`resetDistributionPanelChannel`, `resetDistributionPanelMain`). `groundingPoint` is "topology-only" and contributes no MNA branch; `terminalBlock` and `junctionBox` are also pure-topology (skipped by both the netlist `for...of branches` loop and `mna.stampsForBranch`). `persistBlownState` + `resetSim` mirror per-channel and main trips into / out of params for cross-solve persistence.

**Configurable busbar (`tapCount`, 2–24, default 10):** the busbar is a dynamic-port component just like the fusebox. `params.tapCount` drives `getPortsForNode(data)` to build the port set on demand, splitting evenly between the top and bottom edges (top gets the extra when odd). Port IDs stay stable (`p1`, `p2`, …) so designs saved before the param existed still resolve cleanly — `clampTapCount` defaults to `BUSBAR_DEFAULT_TAPS=10` when missing. Inspector exposes a numeric `Taps` field that routes through a dedicated `setBusbarTapCount` store action (clamps + flushes React Flow's handle cache via the existing `useUpdateNodeInternals` effect, which now also watches the busbar `tapCount`). Edges referencing a port that no longer exists after a shrink are NOT pruned — same shrink behavior as fusebox sockets, so growing the count back resurrects the wire (the netlist already maps unknown ports to `-1` and the solver ignores those branches). `params.polarity` (`positive` | `negative`) is also a **render hint**: `getPortsForNode` stamps the chosen polarity on every generated stud so `portColor()` renders them red or near-black, `ComponentNode.baseColor` swaps the body wash (rose for +, slate-950 for −), and a marine-style coloured rail (red or black) is painted across the body inside the rotated inner layer, before the labels in source order so they render on top. Solver / netlist still treat the busbar as a pure topology node — polarity is purely visual.

**Switch panel ("pulsantiera"):** marine-style rocker switch panel with N configurable channels (2–8, default 4). Three independent layout options the user toggles via Inspector buttons or the corner ⚡ / 💡 / 🔀 chips: **`withFuses`** (each rocker gets an inline fuse — the panel doubles as a fuse block; effective channel R becomes `contactR + coldR` and the iterative trip-detection loop in `mna.ts` walks them just like fusebox sockets) and **`withIllumination`** (adds an `L+` / `L−` port pair on the right edge for the rocker backlight feed; `mna.ts` stamps a 240 Ω resistor between L+/L− so wiring it to power draws ~50 mA at 12 V — small but real load. The renderer reads `runtime.portVoltages.illum_pos − illum_neg` and when it exceeds 1 V the LIT pill brightens, the L+/L− port labels brighten, and every rocker's OFF half picks up a faint amber backlight wash, mirroring how a real backlit marine panel shows "panel on, this switch off". Both the solver constant `ILLUMINATION_R` in `mna.ts` and the renderer constant `ILLUMINATION_R_RENDER` in `ComponentNode.tsx` need to stay in sync — the latter is only used for the tooltip text), and **`independentInputs`** (default off → "Pattern A": single shared `+ IN` on the left, internal bus, every rocker fed from the same source — what 90% of factory marine panels do; on → "Pattern B": the shared `+ IN` is replaced by N per-channel `in_pos_k` ports rendered as the LEFT half of an IN/OUT pair on the bottom edge under each rocker, so the user can feed each rocker from a different fuse / busbar / source. The `−` return bus stays shared in both modes — even Pattern B real panels share ground internally. The MNA stamp picks `b.portNodes.in_pos` vs `b.portNodes[\`in_pos_${k+1}\`]` per channel; `internalConnections` in `review.ts` likewise narrows from "in_pos ↔ all out_pos_k" to "in_pos_k ↔ matching out_pos_k" so the protection BFS treats each channel as electrically isolated. Edges previously connected to a port that no longer exists after a mode flip are NOT pruned — same shrink behavior as fusebox sockets, so flipping back resurrects the wires). Per-channel state lives in `params.switches[]` (`SwitchChannel = { closed, ratingA, blown, blownAt? }`), pad/truncated by `getSwitchChannels(params)`. Inspector exposes a `SwitchChannelsEditor` (parallel to `FuseSocketsEditor`) with per-row closed checkbox; when `withFuses` is on, also amp input + `STANDARD_FUSE_RATINGS` chips + Replace button. The on-canvas `SwitchPanelBody` renders each channel as a vertical two-half rocker (top "I" = ON, bottom "O" = OFF) with a horizontal pivot line; the active half gets an inset highlight (raised), the inactive half an inset shadow (pressed in) — clearly readable at the small per-channel cell size. Clicking a cell toggles `closed`. A small color-coded fuse-blade chip is overlaid when `withFuses` is enabled. Design Review treats a fused switch panel as a protective device (loads behind it are not flagged unprotected) and runs the same fuse-vs-cable-ampacity / oversized-fuse checks as the fusebox; an unfused panel is transparent (acts like a bank of switches in the protection walk).

**Fuse-box (combo panel):** marine-style multi-socket fuse panel — one shared `+ IN` feeds N configurable sockets through their own fuses, plus a pass-through ground bus (`− IN` wired to every `out_neg_k`). Per-socket controls in the Inspector: insert/remove, amp rating (free input + standard ATC chips), per-socket overcurrent trip with its own "Replace" button. Ports are generated dynamically from `socketCount` (2–12). Each socket cell on the canvas is a drop target for the palette `Fuse` card — drop one to insert (or replace) the fuse there. Two independent layout toggles: ⇄ swap-poles flips ONLY the IN+ / IN− positions on the left edge, ⇅ swap-fuse-rows (`fuseSwapped` param, fusebox-only) puts the fused outputs on top and the ground bus on the bottom. Both are render-only; netlist is unchanged.

**Lamp (preset-driven lighting load):** new polarized 1-in/1-out load that mirrors the generic `load` electrical model but ships with four ready-made marine presets — `ledStrip`, `domeLight`, `floodLight`, `headlight` — selected via `params.preset`. Each preset prefills voltage / power / brown-out defaults from the `LAMP_PRESETS` table in `src/sim/schema.ts` and supplies its own glyph + Tailwind body gradient + MiniMap color, so a dropped headlight visibly differs from a strip without bloating the `ComponentType` union. Effective power is `ratedW × lengthM`: for `ledStrip`, `ratedW` is interpreted as **W/m** and `lengthM` is the actual strip length (default 14 W/m × 5 m = 70 W); other presets default `lengthM=1` so the multiplication is a no-op and `ratedW` reads as plain rated wattage. Same `minV` brown-out check as `load` (uses the preset's recommended floor, e.g. 10.5 V for halogen). Reviewer treats `lamp` exactly like `load` via the new `isLoadType()` helper in `review.ts` — voltage-drop / loadUnprotected / topology checks all pick it up automatically. Adding a fifth preset is one entry in `LAMP_PRESETS`, one block in `en.json`, and the palette renders the new card automatically (see "Palette variants" gotcha in §6).

**Appliance (preset-driven 12V load family):** new polarized 1-in/1-out load that mirrors `lamp` — same generic load MNA stamp (`R = ratedV² / ratedW`), same brown-out / voltage-drop / fuse-protection review paths via the shared `isLoadType()` helper in `review.ts` — but ships with eleven Marine 12V presets via `params.preset`: `fridge` (50 W avg / 80 W peak), `fan` (25 W), `waterPump` (60 / 90), `dieselHeater` (30 / 110), `tv` (35), `router` (12), `laptopCharger` (90), `usbCharger` (12), `cigaretteSocket` (60 W default — outlet itself rated ~12 A so the description warns to fuse it accordingly), `compressor` (180 / 360 — description points at the relay), `winch` (1200 / 2400 — same). Each preset spec in `APPLIANCE_PRESETS` (in `src/sim/schema.ts`) carries its own glyph + Tailwind body gradient + MiniMap colour and a `defaults: { ratedV, ratedW, minV, peakW }` block; `peakW` is **informational only** in Phase 1 (steady-state solver ignores it) but is persisted on the node so Phase 2's transient sim can model start-up surge (compressor kick, winch stall, glow plug) without a schema migration. Adding a twelfth preset is one entry in `APPLIANCE_PRESETS`, one `components.appliance.params.preset.options.<id>` + `components.appliance.presets.<id>.description` block in `en.json`, and the palette renders the new card automatically (Tier C from §11). Reviewer treats `appliance` exactly like `load` / `lamp`.

**Battery chemistry presets (Tier C on `battery`):** the `battery` component is now a five-card palette family driven by `BATTERY_PRESETS` in `src/sim/schema.ts` — `agm` (12.8 V / 0.02 Ω / 100 Ah, default — kept for back-compat with existing designs), `lithium` (LiFePO4, 13.3 V / 0.005 Ω / 100 Ah — flat curve, very low Ri so the bank holds voltage at high discharge), `gel` (12.85 V / 0.025 Ω), `flooded` (12.7 V / 0.04 Ω — cheapest, highest Ri, hydrogen-venting), and `portablePowerStation` (Jackery / EcoFlow class — internal LiFePO4 + DC-DC regulator → tightly regulated 13.0 V / 0.005 Ω / ~80 Ah at 12 V). Each spec carries `glyph`, `bodyGradient`, `miniMapColor`, and `defaults: { ocv, internalR, capacityAh }` — the underlying voltage-source + series-R MNA stamp is unchanged, only the defaults and visual identity differ. `setBatteryPreset(id, presetId)` in `store.ts` atomically reseeds defaults on a preset swap. `getBatteryPreset(params)` resolver. `Inspector.tsx` routes `battery.preset` writes through the dedicated action so swapping cards refills the OCV / Ri / capacity fields rather than leaving stale numbers behind. The on-canvas glyph + body gradient + MiniMap dot are preset-driven; the subtitle now also includes the chemistry name (e.g. "Lithium · 13.3 V · 100 Ah") so multiple banks at a glance read distinct.

**Charge sources (alternator / shore charger / solar / wind / generator / DC PSU) — new `chargeSource` component type:** dedicated continuous power-input under `Sources`, driven by `CHARGE_SOURCE_PRESETS` in `src/sim/schema.ts`. Six palette cards: `alternator` (14.2 V / 0.05 Ω / 100 A — engine-driven, default preset), `shorePowerCharger` (13.8 V / 0.10 Ω / 30 A — multi-stage AC→DC), `dcPowerSupply` (12.0 V / 0.05 Ω / 20 A — bench supply, user-configurable V), `solarPanel` (13.8 V post-MPPT / 0.20 Ω / 10 A — has `irradiance` 0..1 modulator), `windTurbine` (13.5 V / 0.15 Ω / 5 A — has `windSpeed` 0..1 modulator), `generator` (13.8 V / 0.08 Ω / 12 A — DC-tap on a portable petrol/diesel genset). Common params: `preset`, `enabled` (engine on/shore connected/sun out toggle), `outputV`, `internalR`, `currentLimitA`, plus the per-preset `irradiance` / `windSpeed` modulators. **Same MNA topology as `battery`** — voltage source + series R + internal node — but **without `capacityAh`** (these are continuous sources, not energy storage), so they don't contribute to the Design Review's battery-runtime calculation. Two ports (`pos` red, `neg` slate). MNA `case "chargeSource"` in `stampsForBranch` reads `enabled` + `getChargeSourceEffectiveV(params)`: when disabled OR effective V drops below 1 mV, stamps a plain `R_OPEN` between the terminals (electrically disconnected from the bus); otherwise stamps a normal voltage source at `outputV × modulator`. The per-component aggregation pass mirrors battery for the live case (`pc.pos = -i_vs`, `pc.neg = i_vs`) and raises the new `alarms.sourceOverloaded` (warn level) when `|i_vs| > currentLimitA` — the linear stamp doesn't enforce the limit, but the alarm tells the user "real alternator field-limits / shore charger folds back / solar MPPT current-limits / source-side fuse blows here". Reviewer integration: `internalConnections` treats it like a battery (`pos ↔ neg`), `reviewFuseProtection` seeds `batteryPosNodes` from chargeSource branches too (an unfused load wired straight to an alternator + post is just as unprotected as one wired to battery +), `isLoadUnprotected`'s BFS predicate passes through `chargeSource`, and `reviewTopology` treats a connected chargeSource as a valid power source — the "no battery in design" error is suppressed when the canvas has at least one connected chargeSource (bench-test designs, shore-only setups). The disjoint-subnet "main subnet" picker gives chargeSource a `+500` weight (vs battery's `+1000`) so a subnet anchored only to a chargeSource is still considered "main". On-canvas: `ChargeSourceBody` renders the preset glyph, the localized label + user label, an inline ON/OFF chip with preset-aware text ("Engine running / Engine off", "Shore connected / Shore unplugged", "Sun out / Night", etc. — keys live under `components.chargeSource.presets.<id>.{enabledLabelOn,enabledLabelOff}`), a live "{effectiveV} V · → {amps} A / {limit} A" readout (red text when over the current limit), and for solar / wind a horizontal slider for `irradiance` / `windSpeed` so the user can drag the sun in real time and watch the bus react. The chip routes through `toggleChargeSourceEnabled(id)` in the store; the slider uses the same pointer-capture pattern as `DimmerBody`. Inspector hides the irrelevant modulator param (`irradiance` for non-solar presets, `windSpeed` for non-wind) so the form stays clean. Adding a seventh source preset is one entry in `CHARGE_SOURCE_PRESETS`, one block in `en.json` under `components.chargeSource.presets.<id>` (with `enabledLabelOn`/`enabledLabelOff`), one MiniMap colour in `Canvas.tsx`'s `nodeColor` switch — palette card and body show up automatically.

**Smart Controls (palette category + relay preset family + MOSFET switch):** dedicated `smartControl` palette category between `switching` and `protection`, populated by the `relay` `ComponentType` (now lives there instead of `switching`) and the new `mosfetSwitch` type. The `relay` ships **seven palette cards** generated from `RELAY_PRESETS` in `src/sim/schema.ts` (Tier C — same trick as `LAMP_PRESETS` / `SWITCH_PRESETS`): `mechanical` (classic Bosch), `solidStateRelay` (opto-isolated input + opto-MOSFET output stage with off-state leakage modeled via `offLeakageR`), `timerRelay` (persists `delayOnS` / `delayOffS` for Phase 2 transients — Phase 1 still closes instantly once coil clears pickup), `latchingRelay` (impulse / bistable — see persistence note below), `smartRelayModule` (Bluetooth/Wi-Fi brick — palette glyph **📲**, distinct from battery-monitor SmartShunt **📶** — with `moduleQuiescentW` extra MCU draw stamped as a parallel resistor across the coil), `contactor` (windlass-grade 250 A contacts at sub-milliohm with a beefy 9 V pickup coil), and `vsr` (Voltage-Sensitive-Relay / ACR battery combiner — coil pair becomes a SENSE pair across two banks, pickup 13.3 V / dropout 12.8 V, 1 kΩ coil so it doesn't drain either bank, 120 A contacts to parallel start + house banks during charging — the user's "dual battery system" needs nothing more). All six share the **same 4-pin coil + contact MNA topology** and iterative `closedRelays` loop — switching presets via Inspector or the `setRelayPreset(id, presetId)` store action atomically reseeds the preset's defaults (pickup / dropout / coil + contact resistance / rating / preset extras) while preserving the user's `forceState`. **Latching persistence:** the `solveDC` loop normally seeds `closedRelays` empty every solve (so non-latching relays start "released" at power-on), but for latching presets it pre-fills the set from `params.latchedContactsClosed` at the top of `solveDC` and then NEVER releases them on dropout (only on `forceState = "open"` or the dedicated `resetLatchingRelay(id)` store action). The post-solve aggregation writes `runtime.contactClosed` so `persistBlownState` in `store.ts` can mirror it back to `params.latchedContactsClosed` for cross-solve continuity. **MOSFET switch (`mosfetSwitch`)** is its own Tier A+ component — Vgs-driven (not coil-driven) so the iteration uses a parallel `closedMosfets: Set<string>` updated from `|V(gate_pos) − V(gate_neg)|` against `vthOn` / `vthOff` hysteresis; channel stamps `onR` (≈ 50 mΩ for a logic-level FET) when on, `R_OPEN` when off. Same overload alarm (`alarms.relayOverloaded`) as the relay contacts, same isolated-pair `internalConnections` walk in `review.ts` (gate ↔ gate, drain ↔ source — never crosses) so the protection BFS treats the MOSFET as a transparent semiconductor switch. MiniMap dot colour is preset-driven for relays (green = SSR, amber = timer, fuchsia = latching, sky = smart module, zinc = contactor, purple = mechanical) and emerald for `mosfetSwitch`. The `RelayStateBadge` is reused for `mosfetSwitch` (drives `forceState` cycling + lights the inset dot from `portCurrents.drain`) so the on-canvas affordance stays consistent across the family. **Caveats:** timer delays are persisted but ignored in Phase 1 (steady-state); SSR `offLeakageR` is finite (~12 kΩ → ~1 mA at 12 V) so loads behind an "off" SSR see a tiny but real voltage instead of a perfect open; smart-module quiescent uses 12 V as the reference for `R = V² / W` (a 24 V boat sees double draw — fine for now, matches a DC/DC-fed module).

**Relay (4-pin SPST, coil-driven contacts):** new 4-port switching component for cascading-control circuits ("panel rocker → relay → winch"). Coil pair on the left (`coil_pos` = terminal 85, `coil_neg` = terminal 86), **red/black handles** with `flipAxis: "vertical"` (stacked on the left edge). Switched-contact pair on the right (`in` = 30, `out` = 87) — **electrically symmetric** SPST but **amber `signal` handles** on canvas so the switched path reads visually distinct from true ± poles. **Relay is not in `POLARIZED`** — no ⇄ swap-poles chrome (use whole-node rotation if the layout needs mirroring). Galvanically isolated in `review.ts` — `internalConnections` keeps coil and contact pairs separate so the protection BFS doesn't treat coil current as if it reached the load. Coil stamps `coilR` (default 90 Ω → ~133 mA at 12 V → ~1.6 W draw) **always** so wiring the coil costs real current; contact stamps `contactR` (default 5 mΩ) when closed or `R_OPEN` when open. State picked by `params.forceState` (`"auto"` | `"closed"` | `"open"`): `closed`/`open` are manual overrides, `auto` (default) is **driven by the existing iterative solve loop in `mna.ts`** alongside fuse-trip detection. The loop maintains a `closedRelays: Set<string>` parallel to `tripped`; after each `attemptSolve` it walks every `auto` relay, computes `coilV = |V[coil_pos] − V[coil_neg]|`, and toggles set membership per pickup / dropout hysteresis (default `pickupV: 7`, `dropoutV: 3` — must operate ≥ 7 V, releases below 3 V). Hysteresis (pickup > dropout) plus the existing `MAX_TRIP_ITERATIONS = 8` cap guarantee convergence even when closing the contact pulls a sagging bus down past the dropout threshold. Contact overload (`|I_contact| > ratingA`, default rating 30 A) raises `alarms.relayOverloaded` (warn level — same as `wireOverloaded`; real contacts at 2× rating weld closed or burn open). On-canvas `RelayStateBadge` cycler shows live state (amber dot when contact is closed regardless of cause, slate when open) and cycles `forceState` (AUTO → FORCE-C → FORCE-O) on click. The `closedRelays` set is **not** persisted across solves — every solve starts with all auto-relays "released" and the loop runs until coil voltages settle, matching how a real relay behaves at power-on.

**LED controller (PWM / RGB):** new polarized multi-output gating component with a `mode` selector (`pwm` = 1 OUT pair — palette glyph reads as a **PWM pulse** in `CONTROLLER_MODES`, distinct from `relay.timerRelay` ⏱; `rgb` = 3 OUT pairs labelled R / G / B). Topology mirrors a fuse-less fusebox: shared `in_pos` fans out per channel through `R_on` to `out_pos_k`, and the negative bus (`in_neg` + every `out_neg_k`) is pre-merged in `netlist.ts` so it's one electrical node — same code path the fusebox uses. Phase 1 DC steady-state model: each channel is gated by `dutyN > 0` — non-zero duty closes the channel at `onR` (default 50 mΩ MOSFET on-resistance), zero duty stamps `R_OPEN`. The duty value is persisted on the node so Phase 2's transient sim can implement proper PWM averaging (V_avg = duty × V_in) without a schema migration. The controller's own electronics also draw a small quiescent (default 0.6 W at 12 V), modelled as a fixed resistor between `in_pos` and `in_neg`, so the battery still sees a realistic hit even with all channels off. Reviewer treats the controller as a **transparent pass-through** (not a protective device): `walkDownstreamCables` and `isLoadUnprotected` both walk through it so loads downstream of the controller are still under the upstream fuse's umbrella. Mode switches change port count (1 ↔ 3 channels), so `useUpdateNodeInternals` watches `params.mode` (see "Stale handle bounds" in §6).

**Monitoring & Sensors (palette category + meter family):** dedicated `monitoring` palette category at the end of `CATEGORY_ORDER` (between `load` and the implicit "uncategorized" tail), populated by seven instrumentation `ComponentType`s — `voltmeter`, `ammeter`, `wattmeter`, `shunt`, `batteryMonitor`, `multimeter`, `oscilloscope`. Each ships **N palette cards** generated from a Tier-C preset table in `src/sim/schema.ts` (`VOLTMETER_PRESETS`, `AMMETER_PRESETS`, `WATTMETER_PRESETS`, `SHUNT_PRESETS`, `BATTERY_MONITOR_PRESETS`, `MULTIMETER_PRESETS`, `OSCILLOSCOPE_PRESETS` — same trick as `LAMP_PRESETS` / `RELAY_PRESETS`). Adding a new real-world model (a Victron BMV-712 vs SmartShunt 500, a Fluke 87V vs Klein MM700) is one row in the relevant `*_PRESETS` table plus one locale block — no MNA / netlist / review changes. **All meters are non-invasive by construction**: parallel V-sense ports (voltmeter, scope channel, battery-monitor V-sense, wattmeter V-pair) stamp `inputR` (default `METER_DEFAULT_INPUT_R = 10 MΩ` → ~1 µA at 12 V, well below the 1 mA energized threshold); series I-sense ports (ammeter, wattmeter I-pair, shunt, multimeter A-mode) stamp a small `internalR` (default 1 mΩ ammeter; preset-driven for the shunt — `getShuntResistance` returns `ratedMv / 1000 / ratedA`, e.g. 100 µΩ for a 500 A / 50 mV bar). Battery-monitor sense ports + shunt sense screws emit a high-Z stamp purely so the matrix is non-singular; the readings are derived in the renderer from `runtime.portVoltages` directly — `BatteryMonitorBody` reads `vbatt_pos − vbatt_neg` for V, multiplies `(shunt_pos − shunt_neg) × params.shuntScaleAperVolt` for I, and computes time-to-go as `capacityAh / max(I, 0.01)`. **Multimeter** branches on `params.mode` (`"V" | "A" | "R" | "Diode"`): V / R / Diode = high-Z parallel stamp; A = low-R series stamp. The on-canvas rotary dial in `MultimeterBody` cycles modes on click via `updateParam(id, "mode", next)`. **Oscilloscope** is a Tier-B dynamic-port component — `params.channels` (1, 2, or 4) drives `getPortsForNode` via `buildOscilloscopePorts`, laying out `2 × N` probe pairs (`chN_pos` / `chN_neg`) along the BOTTOM edge in pairs. Each channel emits its own galvanically-isolated high-Z stamp; the per-channel readings flow through `runtime.socketsRuntime` (re-using the `SocketRuntimeState` shape — the renderer just interprets it as channel data instead of fuse data) and `OscilloscopeBody` plots them as horizontal traces on a CRT-grid keyed to `voltsPerDiv`. Reviewer treats every meter as a **transparent pass-through** (not a protective device): `walkDownstreamCables` and `isLoadUnprotected` both walk through ammeter / shunt / wattmeter I-pair (real series elements, low-R) AND voltmeter / scope / battery-monitor / multimeter (parallel high-Z taps that carry zero current) so a load reachable only via a meter is still assessed against the upstream fuse — meters never act as fuses. `internalConnections` mirrors the relay's coil↔contact split for the 4-port shunt (`a ↔ b` only — sense screws isolated), the wattmeter (I-pair ↔ I-pair, V-pair ↔ V-pair, never crossing), the battery monitor (every sense pair isolated from every other), and the oscilloscope (each channel pair isolated from every sibling channel). New `alarms.meterOverrange` (warn level) covers voltmeter / battery-monitor lowV/highV breach, ammeter / shunt overcurrent, multimeter A-mode overcurrent, wattmeter I-pair overcurrent. **Over-range thresholds on V** use `|V|` for `voltmeter` and `batteryMonitor` bank sense so reversed probe wiring flips the sign on the readout without false-alarming (still wire red to `+` / black to `−` for intuitive displays). **Palette / body differentiation:** `VOLTMETER_PRESETS` ships three cards only (`panelDigital`, `panelAnalog`, `dmmHandheld` — the redundant `dashboard` needle duplicate was dropped). `WATTMETER_PRESETS` — `panelDigital` is the compact 3-row face; `labMeter` is a taller rack-mount body (LED ears, dual display strip, side range knobs) on the larger default footprint (`width` × `height` **200 × 140** in `COMPONENT_LIBRARY`). `MULTIMETER_PRESETS` — `MultimeterBody` branches on `preset.id`: `handheldGeneric` (slate compact), `flukeStyle` (yellow chassis, oversized dial, TRUE RMS strip, `87V`-style hints), `automotiveDmm` (red body with rubber-boot chamfer + ribbed grips); shared `MultimeterDial` helper. **Probe / handle colours:** meter leads use `positive` / `negative` on schema ports (red/black); the full colour taxonomy (`signal`, `wiper`, `ground`, `neutral`) applies across all components — see **§6 "Port colour taxonomy"**. **POLARIZED set** includes the whole meter family (`voltmeter`, `ammeter`, `wattmeter`, `multimeter`, `oscilloscope`) alongside `shunt` / `batteryMonitor` so the swap-poles button can mirror the body even though MNA remains electrically non-polar (readout sign follows probe order). **`shunt`** power studs are red/black BAT/LOAD and sense screws red/black; **`potentiometer`** A/B/W are red/black/violet. **Phase 1 caveats:** scope traces are flat lines (DC steady-state — Phase 2 transient sim will add waveform plotting along X); battery-monitor SOC is pinned at 100% (Phase 2 will coulomb-count); time-to-go uses the existing `capacityAh / I_battery` formula (matches `reviewBatteryRuntime`). **Ammeters** must be wired **in series** with the conductor whose current you want — parallel placement is a near short (`internalR` ~ 1 mΩ).

**Cable routing & harness bundles:** every edge uses React Flow type `cable` (`CableEdge.tsx`); the path is a polyline from source handle through optional stored `data.waypoints` to the target handle. Double-click inserts a bend; waypoint handles drag with snap targets (`snapPointToTargets` + `buildSnapWaypointTargets` for same wire / same `bundleId`). **Waypoint hit targets:** each bend uses a large invisible flow-space circle (`WAYPOINT_HIT_R` ≈ 18) for grabbing and a smaller visible amber dot (`pointer-events: none`); the wrapping `<g>`’s `onPointerDownCapture` for “click path to add bend” **returns early** when `event.target` is under `[data-cable-waypoint-hit]` so it never `stopPropagation()` before the handle sees the event (otherwise route-edit mode made bends feel unclickable). **`routeEditEdgeId`** in `CableEdgeUiContext` disables `selectionOnDrag` on the pane while editing so panning does not box-select; Esc and pane click clear route-edit and the edge context menu. **Named bundles:** edges may share `data.bundleId`; metadata lives in `cableBundles` on the store (label + optional `color`; stroke uses `bundleColors.bundleStrokeColor` when no custom colour). **`reconcileCableBundles`** drops orphan bundle records, strips `bundleId` from singletons, and runs after edge/node mutations and bulk delete. **Inspector:** single-wire panel edits route (toggle edit mode, waypoint list, reset route) and harness fields; multi-select of wires only shows `MultiEdgeCableInspector` (group / ungroup / harness rename). **Export / share:** `exportDesign` persists `waypoints`, `bundleId`, and optional `cableBundles` on `ExportPayload`; ephemera like `snapTargets` / `bundleOffsetPx` / `bundleStroke` are stripped. **`CableEdgeUiProvider`** wraps the main row in `App.tsx` (Palette + Canvas + Inspector) so the Inspector and canvas share menu / route-edit state; **`ReactFlowProvider`** stays only around `Canvas`.

**Edge-as-cable (mandatory AWG + length on every wire):** every React Flow edge IS a real cable run — there is no longer an "ideal" edge mode. When the user drops a connection between two ports, `Canvas.tsx` intercepts React Flow's `onConnect` and opens a `WireConfigModal` (portaled to `document.body` via `createPortal`, same backdrop-blur containing-block trick as `DesignsModal` — see §6) that requires both gauge (AWG **and / or** mm² — see below) and length (m, > 0). Confirm calls the `addCableEdge(connection, { awg, lengthM })` store action; cancel discards the connection so no edge is created at all. Last-used values are persisted in module-scope `lastWireDefaults` inside `WireConfigModal.tsx` so wiring multiple similar runs is fast. Configured edges show a small mid-edge label (`formatAwgForDisplay(awg) + "AWG · " + length` — integer chip picks read as `12AWG`, mm²-derived fractional AWG reads as one decimal, e.g. `3.3AWG`, so the canvas never shows long float tails) and surface live current, voltage drop, and an "overloaded" warning when |I| exceeds the AWG ampacity (same `wireResistance` / `wireAmpacity` tables as the explicit `wire` component). The Inspector's `EdgeInspector` panel can edit AWG / mm² / length post-creation but cannot revert the edge to ideal mode — to remove a wire the user deletes the edge. Legacy designs with bare or partial `data` are auto-upgraded by `migrateEdges` (defaults: 12 AWG, 0.5 m) at every load boundary (`loadDesign`, `openDesignFromLibrary`, `newDesign`, `importPayloadAsNewDesign`).

**Dual gauge UI (AWG + mm²):** both the `WireConfigModal` and the Inspector's edge panel render two synchronised numeric inputs side-by-side — American Wire Gauge on the left, European mm² section on the right — plus two parallel chip rows (AWG presets `4/0 … 18`, mm² presets `0.75, 1.5, 2.5, 4, 6, 10, 16, 25, 35, 50`). The stored field on `WireEdgeData` stays `awg` (the netlist + ampacity tables key on it), and `wireAmpacity` already interpolates fractional AWG between standard table entries — so picking a 6 mm² chip stamps a fractional AWG that lands cleanly between 8 and 10 AWG without losing precision. Conversion lives in two pure helpers in `src/sim/schema.ts`: `awgToMm2(awg)` (factored out from the existing `wireResistance` formula) and `mm2ToAwg(mm2)` (inverse). The mm² chip "active" highlight uses a 6% relative tolerance so an AWG-driven choice still lights up the closest stocked European size (12 AWG ≈ 3.3 mm² → highlights the 4 mm² chip). When adding more presets, edit `MM2_PRESETS` in `schema.ts` — both surfaces pick them up automatically.

**Protected default template (`d_default`):** the library always contains a non-deletable, non-renameable "Default template" entry seeded from `starterDesign()` (`battery → main fuse → main switch → + busbar → 3× (fuse → load) → − busbar → ground`). Canonical node positions / rotations / widths are **hand-curated** in `starterDesign.ts` (battery on the left rotated 270°, main chain along the top, three branch loads to the right, − busbar below; the middle USB row’s return feeds neg busbar tap `p2` so wires stay tidy). Stable id `DEFAULT_TEMPLATE_ID = "d_default"` lives in `src/library.ts` so the entry survives reloads without name-matching. `loadLibrary()` runs an idempotent `ensureDefaultTemplate(lib)` step on every boot — if no entry has `isDefault: true`, one is prepended and persisted (idempotent: existing user edits to the template are NEVER overwritten on boot, only when the user explicitly clicks "Reset to default" in the Designs modal). `deleteDesign` and `renameDesign` short-circuit on `isDefault: true`; `duplicateDesign` works as usual but the duplicate is a regular non-default entry (so users can fork the template freely). Editing the template is allowed — autosave still syncs into its slot like any other design — but the Toolbar's inline-rename button renders as plain italic text + tooltip when the default is active, and the Designs modal swaps the per-row Rename button for a "Reset to default" button (sky-toned to match the new "Default" badge) and disables the Delete button with a tooltip. The new `resetDefaultTemplate()` store action rebuilds `payload = starterDesign()`, replaces the entry's `payload` + bumps `updatedAt`, and — if the default is the currently-active design — also pushes the fresh payload onto the canvas (deselect + clear sim runtime, same shape as `openDesignFromLibrary`) so the snap-back is instant. **`isDefault` guard lives in three places — keep them in sync:** `src/library.ts` (`deleteDesign` / `renameDesign` short-circuit + `ensureDefaultTemplate`), `src/components/DesignsModal.tsx` (per-row badge / button swap / `startRename` early-out), and `src/components/Toolbar.tsx` (`CurrentDesignName` read-only branch). The `+ New (starter sample)` button in the Designs modal still creates a regular editable copy of the same `starterDesign()` content — the protected entry is the canonical reference, the starter button is the "give me a fresh playground" shortcut.

**Designs library (multi-design save/open):** the user can keep N independent 12 V system designs in a single in-browser library. Toolbar grew a `📁 Designs` button + an inline-editable current-design name (next to the brand). Clicking the button opens `DesignsModal.tsx` — a centered overlay with the design list, per-row Open / Rename / Duplicate / Export / Delete, plus header buttons for `+ New (blank)`, `+ New (starter sample)`, and `Save current as…`. Fidelity is full: the saved unit IS the existing `ExportPayload` (`nodes` and `edges` verbatim), so reopening a design restores every position, `width`/`height`, `data.rotation`, `data.flipped`, every `params` value (including fuse `sockets[]`, busbar `tapCount`, `blown`/`blownAt`), per-edge `sourceHandle`/`targetHandle`, and per-edge `data.{awg,lengthM}` byte-for-byte. Storage lives in a dedicated LocalStorage key `boat12v.library.v1` (separate from the legacy single-slot `boat12v.design.v1`, which is kept around as a session-recovery safety net — both are written on every autosave tick). On first boot after the upgrade `loadLibrary()` migrates any pre-existing legacy autosave into a single entry called "My design" so existing users keep their last session uninterrupted. Imports (`Toolbar` file picker) and shared URLs (boot path in `App.tsx`) auto-add to the library as a new entry named after the file or `"Imported {date}"` and become the active design — `App.tsx` strips the URL hash after import so a refresh doesn't keep cloning the same shared design. The active library id drives autosave: when `currentDesignId` is set, the 250 ms debounced subscriber in `App.tsx` calls `useAppStore.getState().syncCurrentToLibrary()` after `autosave(state)`, which serializes the canvas via `exportDesign` and bumps the active entry's `updatedAt`.

**Share URL (encode + receiver + toolbar UX):** `encodeShareUrl` / `tryDecodeShareUrl` in `persistence.ts` put the full `ExportPayload` in `location.hash` as `#d=<base64>` (same JSON shape as file export). The wire format is **URL-safe base64** (RFC 4648 §5: `-`/`_`, strip `=` padding) over **UTF-8** via `TextEncoder` / `TextDecoder`, so Unicode in labels survives and chat apps are less likely to mangle classic-base64 `+`/`/`. The decoder still accepts **legacy** standard-base64 links from older builds. The hash match is **anchored** at `#d=` or `&d=` so unrelated keys like `#wid=foo` cannot false-match `d=`; the token may be `decodeURIComponent`-wrapped if something percent-encoded the fragment. Receiver: `App.tsx` calls `tryDecodeShareUrl()` on boot → `importPayloadAsNewDesign` (runs `migrateEdges`) → strips the hash with `history.replaceState` so refresh does not re-clone. **Toolbar Share:** `copyToClipboard` uses `navigator.clipboard` when available, else `document.execCommand("copy")` from a transient textarea (works on `file://` / non-HTTPS where the Clipboard API is absent); if copy fails or the URL is long (~6 KB+), a **popover** below the button shows the link for manual copy. The `<header>` uses **`relative z-20`** because `backdrop-blur` creates a stacking context — without it, an `absolute` popover inside the bar was painted **under** the canvas/Inspector (later siblings won paint order).

**Design Review score:** Lighthouse-style live design-quality grade (0–100 with letter A–F). Implemented in `DesignReview.tsx` as a floating circular gauge on a React Flow `<Panel position="bottom-left">` (**not** bottom-right — that corner is reserved for xyflow `<Controls>` so the two overlays do not collide). Only visible while `simState === "running"` and `simResults.review` is defined (always true after `runSolve`). Click expands into a ~360 px card with six weighted category bars and clickable issue rows. **Locate:** tapping an issue with `review.locate` calls `IssueRow`'s handler: resolve `ReviewIssue.componentId` / `componentIds[]` against the live canvas — **ids may reference a React Flow node OR an edge** (fuse-vs-cable issues use the **edge** id as `componentId`; previously only node selection ran, so Locate did nothing visible for cables). Matching an edge selects it via `setSingleSelected("edge", id)` and zooms via `useReactFlow().fitView()` to `{ source, target }` bounding nodes (fitting the edge alone has zero area). Multi-node topology issues keep `setSelectedNodeIds(ids)`. **`fitView` options:** animated `duration: 500`, `padding: 0.5`, `maxZoom: 1.6`, queued in `requestAnimationFrame` after selection so the viewport animates cleanly. Fuse-vs-cable copy (`review.issues.fuseExceedsWireAmpacity`, `fuseboxSocketExceedsWireAmpacity`) explains **fault-protection risk** — steady load below cable ampacity is fine; danger is overload/short pulling current *between cable ampacity and fuse rating*, where wire melts before the fuse opens (`en.json`; same idea as ABYC fuse ≤ wire ampacity guidance). Categories + weights: fuse-protection (30), wire-margin (25), voltage-drop (20), fuse-sizing fit (10), battery-runtime (10), topology (5). Implemented as a pure `reviewDesign(nodes, edges, netlist, results)` function in `src/sim/review.ts`; called from `runSolve` so the score updates on every change while running.

## 6. Important implementation decisions / gotchas

- **Ground node is always electrical node 0.** If no `ground` component exists in the design, `netlist.ts` synthesizes one to keep the matrix non-singular.
- **Busbars and ground contribute no branches** — they're pure topology. All ports of a busbar are pre-unioned in the netlist.
- **Battery = ideal voltage source + series internal R**, modeled by inserting an internal node and a resistor (cleaner than augmented MNA with series R).
- **GMIN = 1e-9** added to every node's diagonal to keep singular sub-circuits solvable. Open switch / blown fuse modeled as `R_OPEN = 1e9`.
- **Iterative fuse-trip resolve (`mna.ts`).** A single MNA pass would stamp every fuse at `coldR` (≈3 mΩ) regardless of overcurrent — the post-solve "did `|I| > rating`?" check could *raise an alarm* but the matrix it just solved still showed full current downstream of the doomed fuse, so wires kept lighting up and loads kept seeing 12 V right next to a "BLOWN" badge. `solveDC` now wraps the build-and-solve in a trip-detection loop (cap = `MAX_TRIP_ITERATIONS = 8`): solve → for every not-yet-tripped fuse / fusebox socket recompute `i = (vᵢₙ − vₒᵤₜ) / coldR` → if `|i| > rating`, add the branch key (`<fuseId>` for standalone, `${fuseboxId}::s${k+1}` for sockets) to a `tripped` set, push the `alarms.fuseBlown` alarm with that **pre-trip** current, and loop. Next iteration's `stampsForBranch` reads the same `tripped` set and uses `R_OPEN` for those branches, so the final solve has the post-trip steady state — downstream port currents collapse to ~0, the edge animation stops, and downstream loads stop showing nominal voltage. Brown-out / wire-overload checks run only against the *final* attempt, so transient intermediate states never spawn spurious alarms. The per-trip `LocalizedMessage` is also stashed in `tripFaults` so the runtime `fault` field on the component carries the actual blow current (not the post-trip ~0 A reading) — Inspector and badge tooltip stay informative. **The same loop also resolves relay coil-driven contact state** via a parallel `closedRelays: Set<string>`: after each attempt, every `forceState: "auto"` relay has its coil voltage recomputed and is toggled in/out of the set per pickup / dropout hysteresis. The loop break condition is now `!anyNewTrip && !anyRelayChange`, so a cascading control chain (panel rocker → relay coil → winch) settles in one solve. `closedRelays` is per-solve (no cross-solve persistence) — every solve starts with all auto-relays released and the loop runs until coils settle, which matches real-hardware power-on behaviour. Manual overrides (`forceState === "closed" | "open"`) bypass the set entirely.
- **Persisting blown state + trip current across solves (`store.ts` + `params.blownAt` / `FuseSocket.blownAt`).** The `tripped` set inside `solveDC` is per-solve-call only; without persistence, the very next solve (next drag tick, next param edit) would re-stamp the fuse as `coldR` and re-trip it on every frame. `runSolve` now post-processes the solver output through `persistBlownState`: when `perComponent[id].blown === true` but `params.blown !== true` (or per-socket equivalent), it writes the trip back into `params.blown` / `params.sockets[k].blown` AND mirrors the pre-trip current from `runtime.tripCurrent` into `params.blownAt` / `socket.blownAt`. The updated `nodes` array is returned as part of the runSolve payload; callers `Object.assign(next, runSolve(...))` already, so the persisted nodes flow into the same `set()` payload — no double-render, no second solve. **Why `blownAt` matters:** alarms are only emitted by the iterative loop for **new** trips. Without `blownAt`, the very next solve after a trip would produce an empty alarms array and the StatusBar would flip from "fuse blown at 100.0 A" to "All clear" on the next mouse move — making it impossible to tell what happened. After the iterative loop in `solveDC`, a "still-blown" pass walks every fuse / socket where `params.blown=true` (or `s.blown=true`) but no new trip fired this solve, and re-emits the `alarms.fuseBlown` alarm using `params.blownAt` for the current. If `blownAt` is missing (legacy designs imported pre-feature), the message renders `— A exceeds X A rating` instead of a number — readable but loud about the missing data. The trip stays sticky (matching real hardware) until the user hits **Reset Faults** in the Toolbar, which clears `params.blown`, deletes `params.blownAt`, clears every fusebox socket's `blown` and `blownAt`, and re-solves. `persistBlownState` returns the original `nodes` reference unchanged when nothing tripped this solve, so React Flow does not re-mount nodes on no-op solves.
- **Every edge is a real cable; no ideal-merge mode.** Every React Flow edge in `s.edges` MUST carry `data: { awg: number, lengthM: number > 0 }`. Three things enforce this invariant:
  1. **Creation gate** — React Flow's `onConnect` is intercepted in `Canvas.tsx` to open a `WireConfigModal`. The user picks AWG + length and the connection is committed via the store's `addCableEdge(connection, { awg, lengthM })` action. Cancel = no edge created. Self-loops on the same handle are rejected before opening the modal.
  2. **Editing gate** — `updateEdgeData(id, patch)` (the only post-creation mutator) silently drops any patch that would leave `awg` non-numeric or `lengthM <= 0`, and backfills with the migration defaults (12 AWG / 0.5 m) if the existing edge is somehow missing a field. There is NO `null`-patch / "reset to ideal" branch anymore.
  3. **Migration sweep** — `migrateEdges(edges)` is called inside `loadDesign`, `openDesignFromLibrary`, `newDesign`, and `importPayloadAsNewDesign` (which together cover legacy autosave restore, library opens, file imports, the URL-hash share path, and the starter-design seed). Any edge missing valid `data` gets `{ awg: 12, lengthM: 0.5 }` filled in. Returns the same array reference when nothing needed patching, so React Flow doesn't see spurious churn on already-clean designs.

  The netlist always emits a `wire`-typed Branch (`kind: "edge"`) for every edge — the MNA wire stamp + ampacity check populates `perComponent[edge.id]` (no node has that id, so it's a private slot) and the perEdge builder reads it back to populate `EdgeRuntimeState.{voltageDrop,overloaded}`. `isEdgeWire(e)` in `netlist.ts` now reads as "always true for any wired edge" but defensively still checks `e.sourceHandle && e.targetHandle && data.{awg, lengthM > 0}` so a hand-edited LocalStorage blob that slipped past `migrateEdges` falls back to ideal-merge behaviour instead of crashing the netlist build. Inspector's `EdgeInspector` renders when exactly one edge is selected and zero nodes are. Mid-edge `XAWG · Y.YYm` label is still added by `Canvas.tsx`'s `decoratedEdges` memo (same allocate-only-on-change rule as className, to avoid re-mount stutter).

  **Behavioural change for existing designs.** `migrateEdges` upgrades any previously-ideal edge to 12 AWG / 0.5 m on first load — adds tiny resistance everywhere → solver currents / voltage drops shift slightly vs. the pre-migration baseline. Acceptable: the values are realistic and the user can edit per-wire afterwards, and the alternative ("everything is zero-resistance until the user opts in") is exactly the trap that caused the 4-AWG-without-length bug we just fixed.
- **Cloud backup is best-effort, anonymous, and gated entirely by env vars — never block the solver / persistence flow on it.** `src/cloud.ts` exposes `pushDesign` / `softDeleteDesign` / `syncLibrarySnapshot` / `isCloudEnabled`. The Supabase client is lazy-built from `import.meta.env.VITE_SUPABASE_URL` + `VITE_SUPABASE_ANON_KEY`; when either is missing, every export returns immediately so no network call is ever made. `App.tsx` runs a SECOND debounced subscriber (5 s, separate timer from the 250 ms LocalStorage autosave) that calls `syncLibrarySnapshot(state.library.designs)`; dedupe inside the cloud module is keyed on `updatedAt` so unchanged entries are skipped. The protected default template (`isDefault === true`) is never uploaded — the canonical content is the same for every browser, just noise on the server side. Soft-delete is the ONLY non-snapshot path: `deleteDesignInLibrary` in `store.ts` follows its `saveLibrary(lib)` with a fire-and-forget `cloudSoftDeleteDesign(id)` that stamps `deleted_at = now()` so the owner can still inspect what was there. **Never make any solver / netlist / review code path read from `cloud.ts`** — the simulator must work offline, with cleared site data, behind corporate proxies, etc. Errors are swallowed via a single-shot `console.warn` so a flaky network doesn't spam devtools. Anon attribution id (`boat12v.cloud.anonId.v1`) is generated lazily on first push; clearing site data resets it (a "new" user appears on the server, the old rows stay attributed to the old id — acceptable, this is observability not auth).
- **`isDefault` library guard is duplicated across three files — keep them in sync.** The protected default template (`DEFAULT_TEMPLATE_ID = "d_default"`) is enforced at three layers: (1) `src/library.ts` — `deleteDesign` / `renameDesign` short-circuit on `target.isDefault === true`, and `loadLibrary` calls `ensureDefaultTemplate` to re-seed the entry whenever it's missing (idempotent — never overwrites existing user edits to the template, only the user-driven `resetDefaultTemplate` action does that); (2) `src/components/DesignsModal.tsx` — per-row "Default" badge, Rename → "Reset to default" button swap, Delete disabled with tooltip, `startRename` early-outs on `isDefault`; (3) `src/components/Toolbar.tsx` — `CurrentDesignName` renders the active design name as italic plain text (not a button) when `currentDesignId === DEFAULT_TEMPLATE_ID`. **If you add a new "modify a library entry" code path (rename, delete, replace payload destructively), repeat the `isDefault` check at every layer above the helper** — the helpers are the last line of defence, but a missing UI guard lets the user click a button that silently no-ops, which reads as a bug. Adding new locked attributes (e.g. "the default template can't be exported") is the same pattern: `library.ts` short-circuit + UI button swap + locale string.
- **`useAppStore` selectors must return stable snapshots.** Zustand hooks through React's `useSyncExternalStore`: if the selector returns a **new array/object every call** (e.g. `s.edges.filter(e => e.selected)`), React treats the snapshot as changed on every render → "getSnapshot should be cached" warning and **maximum update depth exceeded**. Derive counts / ids as primitives (`reduce`, `find()?.id ?? null`) or use `useShallow` only when returning composite objects that shallow-compare equal. See `Inspector.tsx` edge-selection branch.
- **Selection model — read this carefully, it's been iterated multiple times:**
  - `selectionOnDrag={true}` + `panOnDrag={[1, 2]}` so left-drag = box select, middle/right-drag = pan.
  - Plain (no Shift/Ctrl/Meta) clicks call `setSingleSelected(...)` to force exactly one element selected — protects against `selectionOnDrag` mis-interpreting a tiny twitch as a sub-pixel selection box.
  - `boxSelectingRef` flag in `Canvas.tsx` is set on `onSelectionStart`, cleared on `onSelectionEnd`. While set, the wrapped `onEdgesChange` filters out every `select` change so wires inside a selection rectangle are ignored. Keeps the "N items selected" count accurate from the first frame of the drag.
  - Floating "N items selected" pill (top-center Panel) only shows when count > 1.
  - Native `deleteKeyCode={["Delete","Backspace"]}` handles multi-delete. `removeSelected` action also clears orphaned edges connected to deleted nodes.
- **NodeResizer** lives inside `ComponentNode` and is only `isVisible` when the node is selected. The wrapper div uses `w-full h-full` so React Flow controls dimensions.
- **Interactive controls inside nodes (switch toggle, REPLACE button)** must have `nodrag nopan` classNames + `onMouseDown` stopPropagation — otherwise React Flow steals the click for drag.
- **Design Review panel**: floating overlay uses `nodrag nopan` and stops propagation on `mousedown` / `click` so React Flow pan/drag does not steal gestures. Placement is **`bottom-left`** to avoid stacking on xyflow **`Controls`** (**`bottom-right`**). `Canvas.tsx` gates on both `simState === "running"` and `simResults?.review !== undefined` (defensive; `runSolve` always merges `review` today). **Locate row click** Resolves issue targets as node ids or edge ids, selects appropriately, runs `fitView` to bounded nodes (`DesignReview.tsx` + `useReactFlow`). **Fuse-exceeds-cable wording** emphasizes fault window (wire melts before fuse if current falls between ampacity and rating), not "burns at normal steady load".
- **Schema as source of truth**: `paramSchema` in each component definition drives the Inspector form. Adding a param = one line in schema, no UI changes needed.
- **Display-only orientation**: each `ComponentData` carries optional `rotation` (`0|90|180|270`) and `flipped` (boolean). Both are render-time only — `ComponentNode.mapPort()` re-maps each schema port's `position`/`offset` so React Flow's `Handle` lands in the right spot, and edges (which target port IDs, not screen coords) re-route automatically. Solver / netlist ignore them. `rotateNode` in `store.ts` also swaps the node's `width`/`height` when crossing 0↔90 / 180↔270 so the body looks naturally tall vs wide. Swap-poles button is only shown on polarized parts (`battery`, `chargeSource`, `load`, `lamp`, `appliance`, `controller`, `busbar`, `fusebox`, `switchPanel`, `potentiometer`, `shunt`, `batteryMonitor`, plus the meter family — `voltmeter`, `ammeter`, `wattmeter`, `multimeter`, `oscilloscope` — whose probes are colour-coded red/black like real gear, plus the protection family — `circuitBreaker`, `groundFaultProtection`, `surgeProtector`, `reversePolarityProtection` — whose IN / OUT direction matters for the user even though the MNA stamps are non-polar); the `POLARIZED` set is duplicated in three files (`ComponentNode.tsx`, `Inspector.tsx`, `Canvas.tsx`) — keep them in sync. The `relay` is **not** polarized for ⇄ (coil pins use red/black + `flipAxis: \"vertical\"` only for stacked layout; contact `in`/`out` are amber `signal`). **`mosfetSwitch`** gate pair is red/black; drain/source are amber `signal` — also **not** in `POLARIZED`.
- **Port colour taxonomy (`portColor()` in `ComponentNode.tsx`, `Polarity` union in `src/sim/types.ts`).** Every React Flow handle gets its background colour from a single function keyed on the schema port's `polarity`. Six values, color-by-function:
  - `positive` → **red** `#ef4444` — true + pole (`battery.pos`, `load.a`, `lamp.a`, `appliance.a`, `busbar` when `params.polarity = "positive"`, `fusebox.in_pos`, `switchPanel.in_pos`, `controller.in_pos`/`out_pos_k`, every meter's red probe).
  - `negative` → **near-black slate** `#1e293b` — true − pole.
  - `signal` → **amber** `#f59e0b` — switched / fused / protected output. Used for `fuse.b` (the post-fuse side), `relay.in` / `relay.out`, `mosfetSwitch.drain` / `mosfetSwitch.source`, `selector.c` (common output), `rotary.c`, `fusebox.out_pos_k`, `switchPanel.out_pos_k` (BOTH Pattern A and Pattern B). The IN side of those pairs stays red so the bottom edge of a switch panel reads "red IN → amber OUT" instead of two stacked reds.
  - `wiper` → **violet** `#a855f7` — `potentiometer.w` (the signal tap; A and B remain red/black).
  - `ground` → **green** `#10b981` — `ground.g`.
  - `neutral` → **slate** `#94a3b8` — pass-through conductor with no role: `wire.a`/`b`, `dimmer.a`/`b`, `switch.a`/`b`, `selector.i1`/`i2`, `rotary.i_k`, `fuse.a` (input side). Default for any port that omits `polarity` so unconfigured ports never look like half-finished red dots. **When you add a new component or dynamic-port builder, declare `polarity` on every port** — this is exhaustive over the union, so TypeScript will not flag the omission, but the canvas will render slate handles on every port until you do.
- **Per-port flip behavior** (`Port.flipAxis`): how `mapPort` treats the port when `flipped === true`. Three modes:
  - `"horizontal"` (default) — true mirror across the vertical axis. `left↔right` ports swap edges; `top`/`bottom` mirror their offset (`1 - offset`). What batteries / loads / busbars use.
  - `"vertical"` — stay on the same edge, mirror offset only. For polar pairs that share an edge (fusebox `in_pos` + `in_neg` are both on the left, so flipping should swap their stacked vertical positions, not punt them to the right edge).
  - `"none"` — flip is a no-op for this port. For ports whose physical placement should be invariant under "swap poles" (fusebox per-socket OUT terminals — the user wants only IN polarity to swap, the socket grid to stay in place).
- **Stale handle bounds** — React Flow caches every handle's bounding rect on mount and uses that cache for hit-testing, connection routing, and edge endpoint geometry. If a handle's `position`, `offset`, or the host node's dimensions change WITHOUT React Flow being told, the cache goes stale and clicks on the visually-correct handle resolve to whichever handle USED to be there (wires start from the wrong port). `ComponentNode.tsx` runs `useUpdateNodeInternals(id)` inside a `useEffect` keyed on every layout-affecting prop (`rotation`, `flipped`, `nodeW`, `nodeH`, fusebox `socketCount` / `fuseSwapped`, busbar `tapCount`, switchPanel `switchCount` / `withFuses` / `withIllumination` / `independentInputs`, controller `mode`, rotary `positionCount`, multimeter `mode`, oscilloscope `channels`, terminalBlock `rowCount`, groundingPoint `studCount`, junctionBox `groupAPortCount` / `groupBPortCount`, distributionPanel `circuitCount`) to flush the cache whenever those change. **If you add a new dynamic-port component or a new render-only orientation flag, add it to that effect's dependency list.**

- **Topology-only components are SKIPPED by the netlist branch loop** — `busbar`, `ground`, `terminalBlock`, `groundingPoint`, and `junctionBox` all pre-shape the union-find graph (`busbar` / `groundingPoint` collapse every port; `terminalBlock` unions each row's `_a ↔ _b` independently; `junctionBox` unions `a_*` together and `b_*` together) but contribute NO MNA branch. They're filtered out by the `if (n.data.type === "ground" || n.data.type === "busbar" || ...)` guard at the top of `netlist.ts`'s branch-construction loop and by a matching `case` block in `mna.stampsForBranch`. **Don't add a passive splice-point as a real branch** — every "wire" through these components has zero MNA cost. `distributionPanel` does NOT belong to this group: its main+branch breaker chain emits real per-channel resistor stamps and participates in the iterative trip-detection loop just like a fused `switchPanel`.

- **`distributionPanel` two-tier iterative trip detection** — the iterative loop in `solveDC` runs per-circuit breaker checks first (using the same shape as `fusebox` / `switchPanel withFuses`, but with `alarms.breakerTripped` and a synthetic key `${id}::s${k+1}`). Then on each pass it sums |I_branch| across **closed and not-yet-tripped** channels and compares against `params.mainBreakerRatingA`; if exceeded, it adds the synthetic main key `${b.id}::main` to `tripped` and emits `alarms.distributionPanelMainTripped`. Because branch trips reduce total current first, the cascading order is "main trips last" — the loop converges on the smallest set of trips that brings the panel within compliance. The stamp pass gates every channel through `mainGate = mainClosed && !mainTrippedParam && !tripped.has(mainTripKey)`, so once the main flips, every channel goes `R_OPEN` on the next attempt. The post-solve aggregation builds `socketsRuntime[]` per branch (re-using the `SocketRuntimeState` shape from fusebox) AND surfaces the main-breaker fault on the component-level `fault` slot when it's the main that tripped. `persistBlownState` mirrors both per-circuit `tripped` and `mainTripped` (+ `trippedAt` / `mainTrippedAt`) into params; the `RESET` pills in `DistributionPanelBody` and the dedicated `BreakerChannelsEditor` route through `resetDistributionPanelChannel` / `resetDistributionPanelMain`.
- **Palette variants (preset-driven cards) — read this before adding more lighting/controller/switch flavours.** `lamp`, `controller`, `switch`, and `rotary` surface MULTIPLE palette cards that all create the SAME `ComponentType` underneath, just with different `params.preset` / `params.mode` baked in (e.g. `switch.toggle` … `switch.killSwitch`, `rotary.rotary` / `rotary.keySwitch`). Plumbed through three pieces: (a) `ComponentDefinition.paletteVariants?: PaletteVariant[]` in `src/sim/types.ts`, populated from data tables (`LAMP_PRESETS`, `CONTROLLER_MODES`, `SWITCH_PRESETS`, `ROTARY_PRESETS`) in `src/sim/schema.ts`; (b) `Palette.tsx` renders one card per variant when present (and skips the plain card), drag carries `DRAG_VARIANT_MIME` alongside `DRAG_MIME`; (c) `Canvas.onDrop` looks the variant up by id, pulls `paramOverrides`, and passes them as the third arg to `addComponent(type, position, paramOverrides)`. The on-canvas glyph + body gradient are picked by resolver helpers (`getLampPreset`, `getControllerMode`, `getSwitchPreset`, `getRotaryPreset`) in `ComponentNode.tsx`, so post-drop edits to `params.preset` / `params.mode` re-skin the body live. **Adding another preset variant is typically one row in the data table + locale + nothing else** — no palette plumbing changes. Avoid introducing a new `ComponentType` per preset when electrical behaviour stays the same; netlist / mna / review paths multiply by `ComponentType`. **Variant builders should also forward a `wiringGuide` field** (read from `C.<type>.presets[id].wiringGuide` or `C.<type>.modes[id].wiringGuide`) onto each `PaletteVariant` so the palette's info-icon popover surfaces preset-specific wiring tips; if a variant doesn't ship its own guide, `entriesForType` in `Palette.tsx` falls back to the type-level `components.<type>.wiringGuide`.
- **Edge-flow animation direction** is derived from the **signed** current at the source-side handle in `mna.ts` (with a fallback to the negated target-side current when the source is a busbar/ground that has no `perComponent` entry). `EdgeRuntimeState.reverse` is `true` when current physically flows target→source instead of source→target; `Canvas.tsx` adds the `edge-reverse` class so CSS sets `animation-direction: reverse`. Without this the dash-flow always runs source→target and looks "backwards" on any wire the user dragged from the negative end first.
- **Battery selector, position `both`:** closing both contacts ties the two inputs together *through* the switch plus whatever is on the common output. The solver computes a single steady-state: if the two banks are **not** at exactly the same Thevenin voltage (OCV − I·Ri) at their positive nodes, **cross-current** can flow between banks. Then one bank’s + wire can show dash-flow **toward** that battery (current entering the + post — charging / equalization). That is **not** a rendering bug; it is the linear DC model doing its job. Identical OCV labels do not guarantee zero cross-current if returns, wiring, or loads differ. If currents or voltages look physically absurd, treat it like a real bench debug: check for unintended shorts, fusebox return wiring, and whether BOTH is appropriate for the topology.
- **`portCurrents` sign convention is "leaving the component is positive"** — non-negotiable, every component case in `mna.ts` follows it (battery: `pc.pos = -i_vs` is positive when discharging; R-components: `pc.a = -i, pc.b = +i` since current arriving at `a` is leaving < 0; fusebox: `pc.in_pos = -totalIn`, `pc.out_pos_k = +i`, `pc.out_neg_k = -i`, `pc.in_neg = +totalIn`). The signed value matters for edge-direction inference; **changing any of these signs will flip dash-flow direction on real circuits, so audit edges before touching this convention.** The on-canvas badge displays `Math.abs(current)` so users still see a friendly positive amp number even though port-`a` of a load reports a negative leaving-current internally.
- **Selected wire is BRIGHTER, not darker.** xyflow's stylesheet defaults `--xy-edge-stroke-selected-default` to `#555`, which is darker than our overridden `--xy-edge-stroke-default` (`#94a3b8`) — selecting a wire used to dim it (counter-intuitive). `index.css` overrides the variable to `#f8fafc` (near-white) and bumps the selected `stroke-width` to 3 so selection still reads on energized wires (the `.edge-energized` keyframe sets stroke + dasharray, but xyflow's `.selected` rule appears later in the cascade so its `stroke` wins). Keep this override in sync if you change the energized animation colors.
- **Edge animation re-mount stutter**: the `decoratedEdges` memo only allocates a NEW edge object when the className actually changes — otherwise React Flow re-mounts the SVG `<path>` on every solve (which fires every drag tick while sim is running), restarting the dash-flow keyframe and making the animation stutter. The CSS `@keyframes flow` is also tuned so the dash-cycle (`5 3` = 8) matches the per-loop `stroke-dashoffset` traversal (`8 → 0`) for a seamless wrap; if you change `stroke-dasharray`, update the keyframe's start offset too.
- **Magnetic alignment snap** lives entirely in `src/components/Canvas.tsx` as a wrapper around the store's `onNodesChange`. Position changes whose `dragging` field is a boolean (i.e. drag-in-progress AND the final `dragging:false` mouse-up frame) are run through `computeSnap()` in [src/snap.ts](src/snap.ts), which compares the dragged node's edges and centers (left/right/top/bottom + h/v centers) against every other node's same six values; if any axis is within 6 screen pixels (scaled by zoom), the position change is rewritten so the node locks to the alignment and a pink dashed guide line is drawn via the `SnapGuides` SVG overlay (uses `useViewport()` so it stays anchored as you pan/zoom). **Critical: the final `dragging:false` frame must also be snapped** — without it React Flow's drag-start + cumulative-delta math reasserts the raw cursor position on release and the node settles a few px off the alignment. Multi-drag uses the first dragged node as the snap "leader" and applies the same `(dx, dy)` correction to every other dragged node, so group shape is preserved. Holding **Alt** during a drag bypasses snap entirely (tracked via a ref so per-frame snap reads don't trigger re-renders). Guides clear when the final frame fires (and as a safety net on `onNodeDragStop`). The store and solver are untouched — snap is presentation-only.
- **Duplicate** is `duplicateSelected` in `store.ts`: clones every selected node with a fresh ID at +40,+40 offset, deselects the originals, and selects the copies; only edges fully INSIDE the selection are duplicated (so dangling wires don't clone into ambiguous stubs). Triggered by Ctrl/Cmd+D (document-level listener in `Canvas.tsx`, bails out when an editable element is focused), the multi-select pill, the Inspector header, and the right-click context menu.
- **Right-click context menu** is local state in `Canvas.tsx` (not in the store). `onNodeContextMenu` selects the node and opens a fixed-positioned menu near the cursor, clamped to viewport. Items: rotate, **swap poles** (same membership as `POLARIZED` / `POLARIZED_TYPES` — all polarized component types, not just battery/load/busbar), fusebox-specific swap-fuse-rows when applicable, duplicate, delete. Closes on Escape, **primary** pointer down outside the menu (see `pointerdown` **capture** on `window` — React Flow stops pane/node events bubbling to `document`, so bubble listeners miss canvas clicks), `onPaneClick` / `onNodeClick` / `onEdgeClick`, or any item click; the menu calls `e.stopPropagation()` on `onMouseDown` and uses `contextMenuRef` + `contains()` so clicks inside stay usable.
- **NodeResizer hit areas** are widened in `index.css` (`.react-flow__resize-control.line` set to 10px hit area with a 1-px amber visible line via `::after`; corner handles bumped to 12×12) so the edges/corners are easy to grab. Override targets the xyflow CSS — keep the selectors stable.
- **HMR-safe IDs**: components use `${type}_${seq.toString(36)}${rand}` so designs loaded from external sources never collide with newly-created nodes.
- **Design Review checks must distinguish "exists" from "wired in".** Two failure modes from the same root cause:
  - `reviewTopology` originally counted `hasBattery` / `hasGround` by component presence in `rfNodes`. A user could drop a ground on the canvas, never wire it, and the "No ground component" warning would silently disappear even though the netlist still has no real ground (the unconnected ground is invisible to it). Same trap with batteries. The floating-components check on the *next* loop intentionally excludes `ground` and `busbar`, so an unwired ground was completely invisible to the review. Fixed by computing `connectedRfNodes` (every node id touched by any edge) FIRST, then deriving `hasConnectedBattery` / `hasConnectedGround` against it. Distinct messages — `review.issues.batteryNotWired` (severity `error`, same as missing battery — symptom is identical) and `review.issues.groundNotWired` (severity `warn`) — fire when the component exists but has zero edges, with `componentId` set so clicking the issue jumps to it on the canvas.
  - Pattern to remember: **whenever a Design Review check reads "are there any X in `rfNodes`?", ask whether an *unwired* X should still count.** It almost never should. The exclusion list in the floating-components check (currently `ground`, `busbar`) is the correct way to handle "this component type doesn't *need* to be flagged as floating because it has its own dedicated check".
- **Cell grids on dynamic-port components MUST use absolute positioning at `k/(n+1) * 100%`, NOT flex layout.** Both `FuseboxBody` and `SwitchPanelBody` originally laid out their per-channel cells with `flex-1` inside a flex container that had `mx-3 my-2 px-1 py-1 gap-1`. With those margins/padding/gaps, the flex-distributed cell *centers* drift away from the port positions (which are at `k/(n+1)` of the FULL body width — netlist + RF handles use that formula and can't move). For low N (2–4) the drift is ~13 px, barely visible. At N=8 in the switch panel the IN/OUT port pair for rocker #8 ended up clearly to the right of the rocker. The fix (now in place for both fusebox and switchPanel): the cells row is `relative my-2`, the visual chassis is a sibling absolutely-positioned div (`inset-x-3 inset-y-0 bg-slate-950/50 rounded-md border ...`), and each cell is `absolute top-1 bottom-1` with `left: k/(n+1) * 100%`, `transform: translateX(-50%)`, and a width of `(100/(n+1)) * 0.78%` (78% of the inter-port spacing → 22% of spacing distributed as visual gap). **Any new dynamic-port component that wants a per-channel cell grid must follow this same pattern**, NOT flex — otherwise the cells will drift from their handles.
- **Empty fusebox sockets are silent killers — flag them when they're wired.** An empty socket (`!s.present`) stamps as `R_OPEN` in `mna.ts`, so loads wired off `out_pos_k` see ~0 V and never function. The pre-existing `reviewFuseProtection` walked only over `s.present === true` sockets, so an empty-but-wired socket scored 100% protected (the topology BFS treated the dead branch as invisible — no current path = no fuse-protection liability = nothing to flag). The fix lives in `review.ts`: when an empty socket's `out_pos_k` electrical node is shared with any branch *other* than the fusebox itself (read via `adj.nodeToBranchPorts`), we emit `review.issues.fuseboxSocketEmptyButWired` (severity `warn`). On the canvas side, `FuseboxBody` reads `useAppStore(s => s.edges)` and computes `wiredEmptySockets: Set<number>` so empty-but-wired cells get a red dashed ring + `!` glyph + a more aggressive hover title. Switch panels don't need this check — `switchPanel` channels with `withFuses` on always have a fuse, and with `withFuses` off the panel is fuse-less by design (no "empty slot" state exists).
- **Multi-channel component pattern (fusebox + switchPanel + future).** Both `fusebox` and `switchPanel` are instances of the same architecture: a fixed shared rail (typically `+ IN` and `− IN` on the left), a configurable count of per-channel ports generated dynamically, a per-channel state array in `params`, optional in-channel fuse trip handling, and a custom on-canvas body. They are duplicated rather than abstracted on purpose — abstracting two sites is premature; we'll consolidate when a third component joins the family. **If you are reading this because you're adding the third, that is the time to extract the shared helpers** (suggested split: a `useChannelDropTarget(onDrop)` hook, a `<ChannelGrid>` body component, a `dynamicPorts({ countParam, ... })` helper for `schema.ts`, and a generic `setChannelCount` factory for `store.ts`). Until then: copy the closer existing sibling and run §11's checklist top to bottom — it lists every file, in order.
- **Fusebox special-casing** lives in five places, all routed through one helper (`getPortsForNode` / `getFuseSockets` in `src/sim/schema.ts`):
  1. `schema.ts` — `getPortsForNode(data)` returns the canonical port list for every node. For non-fusebox it returns `def.ports`; for fusebox it generates `in_pos`, `in_neg`, plus `out_pos_k` (bottom) and `out_neg_k` (top) for `k = 1..socketCount` at offsets `k/(n+1)`. `getFuseSockets(params)` reads `params.sockets`, padding/truncating to match `socketCount` so the array is always self-consistent.
  2. `netlist.ts` — uses `getPortsForNode` everywhere; for fusebox nodes it pre-unions `in_neg` with every `out_neg_k` (the negative bus is one electrical node), then emits a normal Branch (unlike busbar which is pure topology).
  3. `mna.ts` — `stampsForBranch` has a `fusebox` case that loops `getFuseSockets(params)` and emits one resistor stamp per socket between `in_pos` and `out_pos_k` (`R = R_OPEN` if absent or blown, else `coldR`). The per-component aggregation fills `portCurrents`: positive rail (`in_pos`, each `out_pos_k`) from the fuse-branch solve; **negative rail** (`in_neg`, each `out_neg_k`) gets the matching **return-path** amps (`in_neg = Σ branch current`, `out_neg_k = branch k current`) even though the netlist merges those nodes — otherwise edges touching only busbar+fusebox negative ports never highlight yellow (busbars have no `perComponent`, and zero neg ports made `perEdge` think I = 0). Per-socket overcurrent, `alarms.fuseBlown`, and `ComponentRuntimeState.sockets[]` unchanged. Detected blown state is **runtime-only** (mirrors the single-fuse behavior); the user replaces a socket via the Inspector "Replace" button which sets `sockets[k].blown = false`. **Topology gotcha:** the fusebox's negative bus (`in_neg` unioned with every `out_neg_k`) must tie into the **same** return reference as the battery bank (negative busbar, engine block bus, or `ground` node). Until `− IN` is wired to that network, Design Review often reports **disjoint subnets** — the panel's ground bus is its own electrical island. Wiring `− IN` to a negative busbar (or straight to the common that feeds battery − and hull ground) clears the warning and matches how a real panel shares the vessel's DC−.
  4. `ComponentNode.tsx` — handles iterate `getPortsForNode(data)`. Fusebox renders a custom `FuseboxBody` (color-coded blades, LEDs, labels) instead of the generic glyph row.
  5. `Inspector.tsx` — `socketCount` writes are routed to `setFuseboxSocketCount(id, n)` (resizes the `sockets` array atomically) instead of plain `updateParam`. Below the auto-rendered params, fusebox nodes get a `FuseSocketsEditor` block with per-row insert toggle, free amp input + `STANDARD_FUSE_RATINGS` chip presets, blown indicator + Replace button.
- **`ComponentParams` accepts arrays now.** `ParamValue = number | boolean | string | FuseSocket[]`. The `FuseSocket[]` shape is opaque to the existing schema/Inspector — only the fusebox-specific Inspector path reads/writes it. Persistence (`autosave` / share URL) round-trips it for free since it's just JSON.

### Beginner-visible troubleshooting (relay wiring, brown-out, overload)

Useful when explaining canvas behaviour to a non-electrician user — **not** a bug report channel.

- **4-pin relay dots (fixed layout in `schema.ts`):** left edge = **coil**, top = `coil_pos` (**red**), bottom = `coil_neg` (**black**); right edge = **SPST contacts**, top = `in` (terminal **30**, **yellow** `signal`), bottom = `out` (terminal **87**, **yellow**). The on-canvas dots do **not** print `in` / `out` — users must rely on position + colour; the **Inspector → Live measurements** lists `coil_pos` / `coil_neg` / `in` / `out` with voltages when debugging. Correct minimum wiring: fused `+` → `in`; `out` → load `+`; load `−` and `coil_neg` → common `−`; `coil_pos` → switched `+` (or bus) to energize. Feeding **only** the coil while **`in` floats on the negative rail** gives `V(in)=V(out)` and **zero load current** — looks "broken" but the model is right.
- **`alarms.relayOverloaded`:** contact current `|I| > ratingA`. Winch / high-power `appliance` presets (e.g. 1200 W) draw ~80–100 A at 12 V; a **mechanical** Bosch-style preset defaults to **30 A** contacts — use the **`contactor`** preset (250 A, low `contactR`) for anchor windlasses and similar.
- **`alarms.switchOverloaded`:** switch-contact current `|I| > params.ratingA`. Same warn level as the relay/MOSFET overload — real switch contacts at 2× rating weld closed within seconds. Battery-disconnect (250 A default) and emergency-cutoff (50 A default) presets are sized to ride this; push-button (5 A) and panel-rocker (15 A) trip easily, prompting the user to drive a relay coil instead of carrying load current through a panel rocker.
- **Protection components beyond the fuse (`circuitBreaker`, `groundFaultProtection`, `surgeProtector`, `reversePolarityProtection`).** Four new `ComponentType`s under the `protection` palette category, each driven by a Tier-C `_PRESETS` table in `src/sim/schema.ts` so adding a new real-world model is one row + one locale block. **Circuit breaker** (3 presets — thermal / thermal-hydraulic / blade-style) reuses the fuse MNA stamp (`coldR` closed, `R_OPEN` tripped) and the iterative trip-detection loop in `solveDC` — only the persistence param key (`tripped` / `trippedAt`) and the alarm key (`alarms.breakerTripped`) differ from the fuse. Resettable per-component via the on-canvas RESET pill / the Inspector RESET button (both wired to the new `resetBreaker(id)` store action — mirrors the fuse Replace flow but skips the "this is a single-shot device" framing). **Ground-fault protection** (3 presets — shoreInlet 5 mA / dcLeakage 30 mA / panelMount 100 mA) is a 4-port device (`line_pos`, `line_neg`, `load_pos`, `load_neg`) with two parallel `lineR` stamps (1 mΩ each) that swap to `R_OPEN` together when tripped. Trip rule = `max(|I_pos|, |I_neg|) > sensitivityA` (a single-leg leakage trips even if the other leg shows normal load return). Description discloses the AC-vs-DC honest-model caveat — real GFCI is an AC-leakage concept, the simulator approximates it as a low-current trip in DC steady state. Persists `params.tripped` / `params.trippedAt` and resets via `resetGfp(id)`. **Surge protector** (3 presets — mov12v / tvs24v / marineSurge) is electrically invisible in Phase 1: it stamps a plain `R_OPEN` between `a` and `b`. The aggregation pass compares `|V(a) − V(b)|` against `clampV` (default 16 V) and, when exceeded, emits `alarms.surgeEvent` (warn) plus persists `params.blown = true`. Sacrificial: stays open until the user hits RESET (= replace the device) via the on-canvas pill or `resetSurge(id)`. **Reverse-polarity protection** (3 presets — diode / mosfet / relayBased) is an inline pass-through on the + leg with iterative polarity detection: `solveDC` carries a `reversedRpp: Set<string>` mirroring `closedRelays` / `closedMosfets`, and after each attempt the loop checks `V(a) − V(b)` per RPP branch — negative ⇒ add to set (next attempt stamps `R_OPEN`, alarm `alarms.reversePolarity`); ≥ 0 ⇒ remove from set (small hysteresis, no chatter). The diode preset's forward voltage drop is approximated as a small extra series resistance `Vfwd / max(ratingA / 10, 1)` since Phase 1 is a linear solver — accepted compromise; Phase 2 will swap to a Newton-Raphson V-I curve. All four types are in the `POLARIZED` set across `ComponentNode.tsx` / `Inspector.tsx` / `Canvas.tsx` (mirroring the meter family — the MNA stamps tolerate either wiring but the user expects a defined IN / OUT direction). `review.ts`: `circuitBreaker` and `groundFaultProtection` count as protective devices (stop `walkDownstreamCables` and `isLoadUnprotected`); `surgeProtector` and `reversePolarityProtection` are pass-throughs (a load behind a surge protector still needs its own fuse). `reviewFuseProtection` and `reviewFuseSizing` extend their iteration to flag breakers whose `ratingA` exceeds downstream cable ampacity / is oversized for steady-state load.
- **Fuse form-factor presets (Tier C on `fuse`):** `FUSE_PRESETS` in `src/sim/schema.ts` ships **eight** palette cards from a single `fuse` `ComponentType` — `bladeATC` (default, 15 A), `bladeMini` (mini ATM, 7.5 A), `glassAGC` (cylindrical 5 A glass tube), `MIDI` (50 A bolt-down), `ANL` (200 A marine main), `MEGA` (100 A high-AIC), `MRBF` (100 A battery-terminal mount, ~10 kA AIC — eliminates the unfused leg between the battery + post and a remote inline holder), `classT` (300 A lithium-grade main, ~20 kA AIC). Same MNA stamp / trip loop / `params.{ratingA,coldR,blown,blownAt}` schema — only defaults + body gradient + glyph differ between presets. `setFusePreset(id, preset)` reseeds `ratingA` / `coldR` from the preset defaults and clears any persisted `blown` state so the user "swapping a 15 A ATC for a Class T" gets a clean fresh fuse without manually resetting.
- **Switch presets `batteryDisconnect` and `emergencyCutoff`:** added to `SWITCH_PRESETS` (now nine entries) with their own `params.ratingA` defaults (250 A and 50 A respectively, vs 30 A on the generic toggle). Both latching, the disconnect is normally-open (rotary red knob), the emergency cutoff is normally-closed (red mushroom). Same SPST contact stamp + new `alarms.switchOverloaded` warn-level alarm in the switch aggregation. `setSwitchPreset` reseeds `ratingA` from the preset's default — so a 5 A push-button doesn't silently inherit a 250 A rating after the user clicks "Battery disconnect" then back.
- **Brown-out (`alarms.brownOut`) with "good" AWG:** the edge inspector can show **2 AWG / short** while the load still sags below `minV`. Voltage is lost across **battery internal R** (`internalR` in params — AGM sags more than lithium preset), **each fuse in series** (`coldR` at high I), **relay/contactor contact R**, and **every** resistive edge — not just the last hop. **Two main fuses in series** (e.g. 1500 A + 150 A) adds two drops; the oversized one is often pointless protection-wise. Fix path: remove redundant fuse leg, raise battery preset (lithium), swap to **contactor**, shorten/thicken the *whole* high-current chain (both + and − returns).

## 7. Solver internals (very brief)

- Unknowns = `(N-1) node voltages` + `M voltage-source currents`. Ground is excluded from unknowns.
- Resistor stamp: adds `g = 1/R` to diag, subtracts off-diag.
- Voltage source stamp (augmented MNA): one extra row/col per source with ±1 in the incidence positions and `V` on the RHS.
- Solve `A·x = b` via Gaussian elimination with partial pivoting (`src/sim/matrix.ts`). Small dense matrices only (<200 unknowns expected).
- Phase 1 is fully linear (no Newton-Raphson needed yet). Diodes / non-linear models will require Newton-Raphson iteration in Phase 2+.

## 8. Faults detected today

- **Fuse blown** — instantaneous overcurrent vs `ratingA`. Fires for both standalone `fuse` components and any inserted socket on a `fusebox` (alarm carries the fusebox's `componentId` so the StatusBar links back to the panel). The solver re-runs with the tripped fuse stamped at `R_OPEN` so downstream wires/loads correctly show 0 A in the same solve, and the trip is persisted to `params.blown` so it stays open across subsequent solves until **Reset Faults** is pressed (see "Iterative fuse-trip resolve" gotcha in §6). Phase 2 adds I²t curve.
- **Breaker tripped** (`alarms.breakerTripped`) — same trip rule as a fuse, but on a `circuitBreaker` branch OR on a `distributionPanel` per-circuit breaker. Persisted to `params.tripped` / `params.trippedAt` (standalone breaker) or `params.circuits[k].tripped` / `trippedAt` (panel). Resettable per-component via the on-canvas RESET pill / Inspector RESET button (`resetBreaker(id)` / `resetDistributionPanelChannel(id, k)`); also cleared by global "Reset Faults".
- **Distribution panel main tripped** (`alarms.distributionPanelMainTripped`) — Σ |I_branch| across every closed channel of a `distributionPanel` exceeded `params.mainBreakerRatingA`. Persisted to `params.mainTripped` / `params.mainTrippedAt`. The trip kills every channel via the `mainGate` AND in `stampsForBranch` (whole panel goes to `R_OPEN`). Resettable via `resetDistributionPanelMain(id)`; also cleared by global "Reset Faults".
- **Ground-fault tripped** (`alarms.gfpTripped`) — `max(|I_pos|, |I_neg|) > sensitivityA` on a `groundFaultProtection` branch (default 30 mA). Persisted to `params.tripped` / `params.trippedAt`. Resettable via `resetGfp(id)`. Honest-model caveat: real GFCI works on AC current imbalance which has no DC analogue — the simulator approximates it as a low-current trip in DC steady state.
- **Surge event** (`alarms.surgeEvent`) — `|V(a) − V(b)| > clampV` on a `surgeProtector` branch (warn level). Persisted to `params.blown` / `params.blownAt`. Sacrificial: the device stays at `R_OPEN` until reset via `resetSurge(id)` (the on-canvas RESET pill represents installing a fresh device).
- **Reverse polarity** (`alarms.reversePolarity`) — `V(a) < V(b)` on a `reversePolarityProtection` branch. Detected inside `solveDC`'s iterative loop via the `reversedRpp: Set<string>` (parallel to `closedRelays` / `closedMosfets`); next attempt stamps that branch as `R_OPEN`. Recovery requires `V(a) ≥ V(b)`, which produces a small hysteresis dead-band so the alarm doesn't chatter on a marginal bus.
- **Switch overloaded** (`alarms.switchOverloaded`) — switch-contact `|I| > params.ratingA`. Warn level (real contacts at 2× rating weld closed within seconds). Sized so battery-disconnect and emergency-cutoff presets (250 / 50 A) tolerate the main feed; smaller switches (push-button 5 A, panel rocker 15 A) trip on misuse and prompt the user to drive a relay coil instead.
- **Wire overloaded** — `|I|` over AWG ampacity table.
- **Load brown-out** — load voltage below its `minV`.
- **Source overloaded** — `chargeSource` delivering more than its `currentLimitA`. Warn level. Mirrors what a real alternator field-limits / multi-stage charger fold-back / source-side fuse would do; the linear MNA stamp doesn't enforce the limit.
- **Singular circuit** — solver returns `ok: false`, StatusBar turns red.

Each fault appears in `SimResults.alarms` (info / warn / error), is shown on the StatusBar, and faulty components show a red ring + fault badge.

The StatusBar lists the localized alarm line first; if `en.json` defines `alarms.explanations.<key>` matching the alarm message leaf (e.g. `alarms.brownOut` → `alarms.explanations.brownOut`), a second dim italic line explains *why* in beginner-friendly terms. New alarm types in `mna.ts` should add both `alarms.*` and matching `alarms.explanations.*` when user guidance matters.

**Alarms vs Design Review — keep the distinction.** Alarms are *runtime faults* the solver detects right now (fuse blew, wire melted, brown-out). The Design Review (`src/sim/review.ts`, surfaced via the floating gauge) is a *design-quality grade* — it flags things that would *eventually* bite even if no alarm fires: cables running at 90% of ampacity, fuses oversized for their cable, loads with no upstream protection, voltage drop above ABYC bands, etc. Don't promote review issues into alarms or vice versa: the StatusBar stays focused on "what is broken right now", the gauge stays focused on "how would a marine electrician grade this design". Add new design checks by appending a `reviewX()` function in `review.ts` and a category to the `WEIGHTS` map (weights must continue to sum to 100). Each issue needs both `review.issues.<key>` and `review.suggestions.<key>` strings in `en.json`.

**Disjoint-subnet review issue is multi-component.** The topology check splits the netlist into electrical-island BFS groups, picks the "main" subnet (the one containing a battery — heavily weighted via `+1000` in the scoring; falls back to largest member set if no battery), and emits one orphan-summary issue per non-main island. Each orphan issue carries `componentIds: string[]` plus a localized message that lists the stranded components by label (capped at 6, with a `+N more` suffix beyond that). `IssueRow` in `DesignReview.tsx` reads `componentIds` and routes the click through `setSelectedNodeIds(ids)` (new store action) which sets `selected=true` on every listed RF node and clears all edge selection — so one click on the issue highlights the entire orphan island on canvas. `ReviewIssue.componentIds` is optional; the existing single-`componentId` path is kept for back-compat. To resolve busbar / ground RF nodes (which don't surface as branches), `reviewTopology` reads `netlist.portToElectricalNode` instead of re-running union-find.

## 10. When making changes

1. Use `Read` before editing. Use `StrReplace` for edits.
2. After edits run `npx tsc -b` and `ReadLints`. Fix anything you introduced.
3. **Update `LLM.md`** for anything that changes user-visible behavior, solver faults, file map, i18n keys, or architectural assumptions — so the next session reads correct context.
4. Don't break the data-driven model: new components go in `schema.ts`; new params auto-appear in the Inspector via `paramSchema`.
5. Don't bypass the selection rules in section 6 without strong reason — they were tuned to fix real UX bugs.
6. Don't add comments that just narrate the code; explain non-obvious intent only.
7. Keep the bundle lean — current build is ~536 KB JS / 161 KB gzip.

## 11. Adding a new component — checklist

This project has accumulated a real "shape" for components. **Pick the right tier below and follow it top to bottom — do not skip files; almost every "why doesn't my new component …?" bug is a missed step here.** All paths are workspace-relative.

### Tier A — Simple primitive

> No dynamic ports, no per-channel state, generic glyph + label body, no drop targets. Examples: `battery`, `switch`, `fuse`, `load`, `ground`, `circuitBreaker`, `surgeProtector`, `reversePolarityProtection` (the protection family — even when they iterate inside `solveDC` like fuses / relays, they're still 2-port primitives with no per-channel state). The 4-port `groundFaultProtection` is closer to Tier B in port count but still has fixed (not dynamic) ports.

1. **`src/sim/types.ts`** — add the new string literal to `ComponentType`.
2. **`src/sim/schema.ts`** — add an entry to `COMPONENT_LIBRARY` (`category`, `label`, `description`, `glyph`, `width`, `height`, `ports[]`, `defaultParams`, `paramSchema[]`). Pull every user-visible string from `C.<type>.…` (which reads `src/locales/en.json`).
3. **`src/sim/mna.ts`** — add a `case "<type>":` to `stampsForBranch` (resistor + voltage-source stamps) and to the per-component aggregation switch (compute `portCurrents` honoring the leaving-positive convention from §6, set `energized` / `power`, populate `fault` / `tripCurrent` if it can fail at runtime).
4. **`src/sim/review.ts`** — add a `case "<type>":` to `internalConnections` so the topology BFS knows how current flows through it from each port (return the list of *other* port IDs reachable internally from `enterPort`). Required: TypeScript will not compile without this case (the function is exhaustive over `ComponentType`).
5. **`src/locales/en.json`** — add a `components.<type>` block: `label`, `description`, `ports.<portId>.name` for every port, `params.<key>.{label,help?}` for every param. Schema uses these directly.
6. *(Optional)* If polarized (has + / − ports the user might want to swap), add `"<type>"` to the `POLARIZED` set in **THREE** places: `src/components/nodes/ComponentNode.tsx`, `src/components/Inspector.tsx`, `src/components/Canvas.tsx`. The set is duplicated on purpose — keep them in sync.

That's it. Palette, Inspector form, drag-drop onto canvas, save/load, share URL, autosave, edge highlighting all work for free.

### Tier B — Complex multi-channel component

> Dynamic per-instance port count, per-channel state, custom on-canvas body, possibly per-channel fuse trip, possibly drop-targets. Examples: `fusebox`, `switchPanel`. **Copy the closest existing sibling** — the closer the analog, the fewer surprises.

Everything in Tier A, plus:

7. **`src/sim/types.ts`** — define a per-channel state `interface` (e.g. `FuseSocket`, `SwitchChannel`). Extend `ParamValue` to include `<NewChannel>[]` so `params.<channels>` typechecks.
8. **`src/sim/schema.ts`** —
   - Add `<X>_MIN_…`, `<X>_MAX_…`, `<X>_DEFAULT_…` constants.
   - Add `default<X>Channels(n)` (returns a fresh array of N defaulted channels) and `clamp<X>Count(raw)` (clamps + handles NaN / missing).
   - Add `get<X>Channels(params)` that pads/truncates to match the count param so the array is always self-consistent — every consumer reads through it (mna, store, Inspector, ComponentNode).
   - Add `build<X>Ports(data)` for the dynamic port set; wire it into `getPortsForNode(data)`.
   - Include the channel array in `defaultParams`.
9. **`src/sim/netlist.ts`** — if the component has internally-shared electrical nodes (typically a shared negative return bus across all channels), pre-union those ports inside the `forEach(node)` loop, **excluding** any ports that should remain externally-wirable (e.g. `switchPanel`'s `illum_pos` / `illum_neg`). Mirror the existing `fusebox` / `switchPanel` block.
10. **`src/sim/mna.ts`** —
    - `stampsForBranch`: emit one stamp per channel (typically between `in_pos` and `out_pos_k`); honor `tripped` set + per-channel `blown`.
    - **If channels can blow:** extend the iterative trip-detection loop in `solveDC` (compute pre-trip `i`, compare to `ratingA`, push to `tripped` and emit `alarms.fuseBlown`); extend the post-loop "still-blown" pass that re-emits alarms for already-blown channels using `blownAt`.
    - Per-component aggregation: populate `socketsRuntime` (one entry per channel with `current` / `voltage` / `energized` / `blown` / `fault` / `tripCurrent`), plus `portCurrents` for *every* port including the merged-return ones (see existing fusebox return-rail bookkeeping — without it, edges to busbars don't highlight).
    - Set `perComponent[id].blown` if any channel blew.
11. **`src/store.ts`** —
    - Add to `AppState`: `set<X>Count(id, n)`, `set<X>Channel(id, idx, patch)`, plus `toggle<X>Feature` actions for any boolean params (mirrors `toggleSwitchPanelFuses` / `toggleSwitchPanelIllumination`).
    - Extend `persistBlownState`: when `runtime.sockets[k].blown === true` but `params.<channels>[k].blown !== true`, write back the trip + `blownAt`. Otherwise the iterative loop will re-trip on every solve.
    - Extend `resetSim`: clear `blown` / `blownAt` for every channel of the new type when the user hits "Reset Faults".
    - Each `setX` action: clamp params, replace nodes immutably, **re-solve when `simState === "running"`** via `Object.assign(next, runSolve({ nodes, edges }))` (every existing param-write action does this — skipping it leaves the canvas with stale runtime values).
12. **`src/components/nodes/ComponentNode.tsx`** —
    - Add `"<type>"` to `POLARIZED` if polarized.
    - Extend the `useUpdateNodeInternals` deps to include every new param that changes port count or position (e.g. `switchCount`, `withFuses`, `withIllumination`). Without this, React Flow's handle bounds cache goes stale and clicks target the *previous* port positions — this is the most common dynamic-port bug.
    - Add corner buttons for any feature toggles (the small ⚡ / 💡 chips that appear when the node is selected).
    - Implement a `<X>Body` component (mirror `FuseboxBody` / `SwitchPanelBody`); branch the main `return` to render it instead of the generic glyph row.
    - **Drop targets:** if a channel cell should accept a palette card, copy the `onCellDragOver` / `onCellDragLeave` / `onCellDrop` block from `SwitchPanelBody`. The MIME constant is `DRAG_MIME` exported from `Palette.tsx`; `e.dataTransfer.getData(DRAG_MIME)` returns the dropped component type.
13. **`src/components/Inspector.tsx`** —
    - Add `"<type>"` to `POLARIZED`.
    - In `setParam`, route the count param and any boolean toggles through the dedicated store actions (NOT plain `updateParam` — `updateParam` won't resize the channel array atomically and will leave the array length out of sync with the count).
    - Add toggle buttons for boolean features in the Orientation row (mirror the ⚡ / 💡 buttons for `switchPanel`).
    - Add a `<X>ChannelsEditor` component below the auto-rendered `paramSchema` block (per-row editor: closed/present checkbox, amp input + `STANDARD_FUSE_RATINGS` chips when applicable, blown indicator + Replace button).
14. **`src/sim/review.ts`** —
    - Extend `internalConnections` (Tier A item 4) to handle the dynamic ports — typically `in_pos` reaches every `out_pos_k` (and vice versa), `in_neg` reaches every `out_neg_k`.
    - If the component is sometimes a protective device (has fuses), update `walkDownstreamCables` and `isLoadUnprotected` to either pass through (when `withFuses === false`) or stop at it (when `withFuses === true`).
    - Extend `reviewFuseProtection` and `reviewFuseSizing` to iterate the channel array when fuse-mode is on (mirror the existing fusebox loops).
15. **`src/locales/en.json`** — Tier A's `components.<type>` block plus:
    - `inspector.<XEditor>` block (title, count hint, closed/open labels, blownLabel, replace).
    - `componentNode.toggle<X>` strings for any new corner buttons.
    - `components.<type>.channelTitleClosed` / `Open` / `Fused` / `OpenFused` / `emptyChannelTitle` for hover tooltips.
16. **`LLM.md`** —
    - Add a one-paragraph entry to §2 describing the new component, its params, its fuse / drop / illumination semantics if any, and any non-obvious tradeoffs. Future agents will read this paragraph first; make it concrete (numbers, defaults, where state lives).
    - Add to the appropriate gotcha bullet in §6: at minimum the `useUpdateNodeInternals` dep list and (if polarized) the duplicated `POLARIZED` set.
    - Update the file map in §4 if the component adds a new helper file.
17. **Verify:** run `npx tsc -b` (must be 0 errors — `ComponentType` exhaustiveness will flag any missed switch case in `mna.ts` / `review.ts`) and `ReadLints` (no new lints). Drop the new component on the canvas, wire it up, hit Run, and confirm: edges highlight, runtime badge shows numbers, params edit cleanly, faults persist across solves, "Reset Faults" clears them, save → reload restores it byte-for-byte.

### Tier C — Preset variant of an existing component

> You don't need a new `ComponentType` — you want **another flavour** of an existing one (e.g. a fifth lamp preset like "navLight", or a third controller mode like "addressableRGB"). The underlying MNA stamp / netlist / review behaviour stays identical; only defaults + visual identity change. Examples: every preset under `lamp` and every mode under `controller`.

1. **`src/sim/schema.ts`** — add ONE entry to the relevant data table:
   - For a new `lamp` preset: extend the `LampPreset` union AND `LAMP_PRESETS: Record<LampPreset, LampPresetSpec>` with `glyph`, `bodyGradient`, `miniMapColor`, and `defaults: { ratedV, ratedW, minV, lengthM }`. The `lamp` definition's `paletteVariants` and the `preset` `paramSchema.options` are computed from `Object.keys(LAMP_PRESETS)`, so the new preset auto-propagates.
   - For a new `controller` mode: extend `ControllerMode` and `CONTROLLER_MODES` with `glyph`, `channelLabels` (length = output channel count), `bodyGradient`, `miniMapColor`, and `defaultDuties[]`. `buildControllerPorts` already reads `channelLabels.length` so the right number of ports appears on drop. **If channel count differs from existing modes, double-check the default node `width` / `height` in `COMPONENT_LIBRARY.controller` — RGB at N=3 needs ~200×130 to avoid cramming.**
2. **`src/locales/en.json`** — add the option label and description:
   - Lamp: `components.lamp.params.preset.options.<id>` (palette card label + dropdown label) and `components.lamp.presets.<id>.description` (palette card subtitle).
   - Controller: `components.controller.params.mode.options.<id>` and `components.controller.modes.<id>.description`.
3. *(Optional)* If the new variant has DIFFERENT structural needs (extra param the existing schema doesn't cover, e.g. a "color temperature" knob for one lamp preset), add it to the type's `paramSchema` — schema params are flat per type, so they'll show in the Inspector for ALL presets unless you guard the rendering. Prefer reusing existing knobs (e.g. via `lengthM` as a multiplier) over fragmenting the schema.
4. **`src/components/Canvas.tsx`** — extend the MiniMap `nodeColor` switch with the new `preset` / `mode` value if you want a distinct dot colour. Falls back to the type's default if you skip this.
5. **Verify:** `npx tsc -b` (the union extension will flag any default-table you forgot), then drop the new variant card from the palette and confirm the on-canvas body picks up the right gradient + glyph (driven by `getLampPreset` / `getControllerMode` in `ComponentNode.tsx`, no extra wiring needed).

That's it — no MNA changes, no review changes, no store changes. The whole point of Tier C is that **the simulator and reviewer don't know presets / modes exist**; they're a pure UX layer over the existing component type.

### Why this list and not a framework?

Two complex components (`fusebox`, `switchPanel`) is not enough signal to know which abstraction is right. The duplication is on purpose. **The moment a third component lands** in this same shape (e.g. a "battery selector with N inputs", "relay panel with N coils"), the right move is to extract — `useChannelDropTarget`, `<ChannelGrid>`, `dynamicPorts({...})`, `setChannelCount` factory. Until then, copy + checklist is faster, lower-risk, and keeps each component self-contained for casual readers.

The Tier C "preset variant" pattern (`lamp`, `controller`) IS already an extracted abstraction — `paletteVariants` on `ComponentDefinition`, `DRAG_VARIANT_MIME`, and the `getLampPreset` / `getControllerMode` resolver helpers — because it lets a single component bloom into 4–6 palette cards with zero per-preset code in the simulator core. New "families of pre-configured loads" (e.g. anchor lights / nav lights, or HVAC-style relays) should adopt the same pattern instead of one-component-per-preset.
